## 1. 通用规范

### 1.1 基础约定

- Base URL：`http://localhost:8000/api/v1`（前端开发代理 `/api` → 8000 端口）
- 数据格式：JSON（UTF-8）；文件上传 `multipart/form-data`；流式接口 `text/event-stream`（SSE）
- 时间格式：`YYYY-MM-DD HH:mm:ss`（本地时间）；日期 `YYYY-MM-DD`
- 分页：请求 `page`（从 1 起）+ `page_size`（默认 10，最大 50）；响应 `data: {total, items}`

### 1.2 统一响应体

```json
{ "code": 0, "message": "ok", "data": {} }
```

`code=0` 成功；非 0 见错误码表。SSE 接口不走此格式。

### 1.3 错误码表

| 码 | 含义 | 前端动作 |
|---|---|---|
| 0 | 成功 | - |
| 10000 | 系统内部错误 | 通用错误提示 |
| 10001 | 参数校验失败 | 表单标红提示 |
| 10002 | 资源不存在 | 提示后刷新列表 |
| 10003 | 资源冲突（重复数据） | 提示已存在 |
| 10010 | LLM 调用失败（超时/网络） | "AI 服务暂不可用" + 重试按钮 |
| 10011 | LLM 输出格式异常 | 降级纯文本 / 提示重试 |
| 10012 | 未配置 LLM Key | 引导跳转设置页 |
| 10013 | LLM 连通性测试失败 | 展示失败原因（Key 无效/网络不通/模型不存在） |
| 20001 | 批量导入文件格式错误 | 提示文件要求 |
| 20002 | 批量导入存在非法行 | 展示行级错误清单 |
| 30001 | 指定方向题库无题 | 提示换方向 |
| 30002 | 错题不存在或已掌握 | 提示刷新 |
| 40001 | 面试会话状态非法（已结束等） | 提示会话已结束 |
| 40002 | 面经结构化提取失败 | 提供"仅保存原文"入口 |
| 50001 | Agent 工具参数缺失 | 追问补全参数 |
| 60001 | 语音转写失败 | "转写失败，可重试或直接打字" |
| 70001 | 就业网抓取失败 | 概览区块显示降级文案 |

### 1.4 SSE 事件协议（全部流式接口通用）

```
event: start
data: {"message": "正在分析…"}                       // 连接建立后立即推送（感知延迟优化）

event: delta
data: {"text": "增量片段", "section": "match_score"}   // section 可选，标识报告段落

event: tool_call
data: {"tool_name": "create_application", "args": {...}}  // 仅 Agent 接口

event: done
data: {"record_id": 123, "extra": {...}}                  // 落库 id 与附加数据

event: error
data: {"code": 10010, "message": "..."}                   // 中途失败，已渲染内容保留
```

## 3. 接口详述

### 3.1 通用

**GET /health**

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| - | - | - | - | - |

响应：`{"code":0,"message":"ok","data":{"status":"ok","llm_configured":true}}`。`llm_configured` 供前端在概览提示"未配置 AI"。

### 3.2 今日概览

**GET /overview**

响应 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| upcoming_events | array | 待面试/笔试：`[{application_id, company, position, event_at, status}]`，7 日内按时间升序 |
| application_stats | object | `{APPLIED: n, WRITTEN: n, INTERVIEW: n, OFFER: n, CLOSED: n}` |
| follow_ups | array | 3 天无进展：`[{application_id, company, position, applied_at, days}]` |
| wrong_question_count | int | 到期未复习错题数 |
| campus_events | array | 近期宣讲会 `[{id, title, company, event_date, location, source_url}]` |
| last_crawl_at | datetime/null | 就业网最后抓取时间（null=未抓取/失败） |

### 3.3 投递管理

**GET /applications**

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| status | query | string | 否 | 状态过滤（枚举值） |
| city | query | string | 否 | 城市 |
| company | query | string | 否 | 公司关键字（LIKE） |
| page / page_size | query | int | 否 | 分页 |

响应 items 字段与 3.4 application DTO 一致（不含 remark，列表精简）。

**POST /applications**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| company | string | 是 | 公司名称（≤100） |
| position | string | 是 | 岗位名称（≤100） |
| city | string | 否 | 城市 |
| expected_salary | string | 否 | 期望薪资（自由文本） |
| applied_at | string | 否 | 投递日期，默认当天 |
| channel | string | 否 | 投递渠道 |
| status | string | 否 | 状态，默认 APPLIED |
| next_event_at | string | 否 | 下次笔试/面试时间 |
| remark | string | 否 | 备注 |

响应：`data = application DTO`（含 id）。

**application DTO**（列表/详情/创建通用）：

```json
{"id":1,"company":"浩鲸科技","position":"Java 开发","city":"南京",
 "expected_salary":"13k","applied_at":"2026-09-23","channel":"官网",
 "status":"APPLIED","next_event_at":null,"remark":"","created_at":"...","updated_at":"..."}
```

**GET /applications/{id}**：同上 DTO，含 remark 全文。

**PUT /applications/{id}**：请求体同 POST（全量更新，除 status 外均可改；status 变更走 PATCH）。

**DELETE /applications/{id}**：响应 `data: null`。

**PATCH /applications/{id}/status**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| status | string | 是 | 目标状态（枚举值，合法流转见 SRS FR-004 状态机） |
| event_at | string | 否 | 转为 WRITTEN/INTERVIEW 时可同时更新下次考试/面试时间 |
| remark | string | 否 | 流转备注 |

**POST /applications/import**（multipart）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | file | 是 | .xlsx 或 .csv，≤2MB |

表头：`company,position,city,applied_at,channel,status,remark`（模板接口下载）。响应：`data:{success_count, errors:[{row, reason}]}`；全部行非法返回 20002（errors 非空）。

**GET /applications/template**：返回 xlsx 文件流。

**GET /applications/trend**（对应 FR-005）

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| days | query | int | 否 | 统计最近 N 天，默认 30，最大 90 |

响应：`data:{items:[{date:"2026-09-23", count:3}]}`（按投递日期 GROUP BY，含 0 值日期）。

### 3.4 JD 匹配分析

**POST /stream/jd-analysis**（SSE）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| jd_text | string | 是 | JD 原文（≤10000 字） |
| application_id | int | 否 | 关联投递记录 |

事件流：`delta`（section 依次为 `match_score/scores/strengths/gaps/advice`）→ `done`（`record_id` = jd_analysis_report.id）。用户中途断开：已生成内容落库并标记。

**GET /jd-reports**（query：application_id 可选、page、page_size）

items：`[{id, application_id, company?, score, created_at}]`（company 联表显示）。

**GET /jd-reports/{id}**：`data:{id, application_id, jd_text, report_text, score, created_at}`。

### 3.5 AI 模拟面试

**POST /interview-sessions**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| application_id | int | 否 | 关联投递（有则 company/position 从中带入） |
| company / position | string | 条件必填 | 未传 application_id 时两者必填 |
| direction | string | 否 | 面试方向，默认 GENERAL |
| question_count | int | 否 | 题量 3~15，默认 8 |

响应：`data = session DTO`：

```json
{"id":1,"application_id":1,"company":"浩鲸科技","position":"Java 开发",
 "direction":"JAVA","question_count":8,"status":"ACTIVE","summary":null,
 "created_at":"...","finished_at":null}
```

**GET /interview-sessions**（query：status 可选、page、page_size）。

**GET /interview-sessions/{id}**：session DTO + `qa_list`：

```json
{"id":1,"seq":1,"question":"...","answer":"...","is_voice":0,
 "score":8,"review":"...","skipped":0,"created_at":"..."}
```

**POST /stream/interview-chat**（SSE）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| session_id | int | 是 | 会话 id |
| answer | string | 否 | 本题作答；会话第一题传空串触发开场提问 |
| skip | bool | 否 | true=跳过上一题（不计分，直接下一题） |

事件流：`delta`（section 依次 `review/next_question`；第一题为 `next_question`）→ `done`（`record_id` = 新 interview_qa.id，含 seq）。会话已结束（40001）或已满题量（done 事件 `extra:{session_finished:true}`，前端引导生成总结）。

**POST /stream/interview-summary**（SSE）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| session_id | int | 是 | 会话 id（须含 ≥1 条已完成 Q&A） |

事件流：`delta`（section=`summary`）→ `done`（`record_id`=session.id，会话置 FINISHED）。重复调用返回已有 summary（不重复计费）。

### 3.6 八股陪练

**POST /practice/questions**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| directions | array | 是 | 方向数组（可多选），元素为枚举值 |
| count | int | 否 | 抽题数，默认 1，最大 5 |

响应：`data:{items:[{id, direction, content, qtype}]}`。注意：**不含 answer**（防止先看答案）。

**POST /stream/practice-review**（SSE）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| question_id | int | 是 | 题目 id |
| answer | string | 是 | 用户作答 |

事件流：`delta`（section 依次 `score/review/reference_answer`）→ `done`（`record_id`=practice_record.id；`extra:{wrong_question_id?}`，评分 <6 自动入错题本时返回——该题已在错题本则更新档位并返回原 id）。

**GET /practice/records**（query：question_id 可选、page、page_size）：陪练历史。

**POST /questions**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| direction | string | 是 | 方向 |
| content | string | 是 | 题干 |
| answer | string | 是 | 标准答案 |
| qtype | string | 否 | 默认 SUBJECTIVE |
| source | string | 否 | 默认 AI_GENERATED |

### 3.7 错题本

**GET /wrong-questions**（query：status=`PENDING`待复习/`MASTERED`已掌握、page、page_size）

items：`[{id, question_id, content, direction, source_type, review_stage, next_review_at, wrong_count, mastered_at}]`（content 联表 question）。

**POST /wrong-questions**：两种请求形态（对应两类入本来源）：

- 题库题：`{question_id}`（须存在于题库且未入本，冲突返回 10003）；
- 面试知识点（不在题库）：`{content, answer, direction, source_type:"INTERVIEW"}`——后端先自动创建 question（source=AI_GENERATED）再入本。

**DELETE /wrong-questions/{id}**：`data: null`。

**POST /wrong-questions/{id}/review**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| answer | string | 是 | 复习作答 |

响应 `data`：

```json
{"correct":true,"explain":"判定解析/标准答案","review_stage":2,
 "next_review_at":"2026-09-26 00:00:00","mastered":false}
```

判定：CHOICE 题规则比对；SUBJECTIVE 题 LLM 判定（非流式 JSON 输出）。档位推进规则见数据库设计 3.9。

### 3.8 面经整理

**POST /experiences**：`{company?, position?, source?, original_text}`（original_text ≤10000 字）。响应 experience DTO（含 id）。**只存原文，不触发提取**。

**GET /experiences**（page、page_size）：items：`[{id, company, position, source, item_count, created_at}]`（不含原文，列表精简）。

**GET /experiences/{id}**：experience 全文 + `items:[{id, question, answer_points, source_type}]`。

**DELETE /experiences/{id}**：级联删条目。

**POST /stream/experience-extract**（SSE）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| experience_id | int | 是 | 已保存的面经 id |

事件流：`start`（提取开始状态文案）→ `delta`（提取进度状态文字，不逐字展示 JSON）→ `done`（`extra:{items:[{question, answer_points}]}`，条目已落库）。提取失败发 error（code 40002），原文仍在，前端提供重试/仅存原文。

**GET /experience-items/search**（query：keyword 必填 ≤50 字、page、page_size）

items：`[{id, experience_id, company, question, answer_points}]`（company 联表 experience）。

### 3.9 全局 Agent

**POST /stream/agent-chat**（SSE）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| conversation_id | int | 否 | 不传则新建会话（done 事件回 id） |
| message | string | 是 | 用户输入 |

事件流：

```
delta      → Agent 文字回复增量
tool_call  → {tool_name, args}：写操作类工具（新增投递/状态流转），
             前端渲染"确认卡片"，用户确认后调 3.10 执行接口
done       → {record_id: agent_message.id, conversation_id, extra:{...}}
```

查询类工具（查投递/搜面经/出题等）由后端直接执行，结果以文字+结构化数据（delta 事件 `text` 带 JSON 块）回显。

**POST /agent/tools/{tool}/execute**

| tool | 请求体 | 说明 |
|---|---|---|
| create_application | 同 POST /applications 请求体 | 执行入库，返回 application DTO |
| update_application_status | `{application_id, status, remark?}` | 状态流转，返回 application DTO |

**GET /agent/conversations**（page、page_size）：`[{id, title, updated_at}]`。

**GET /agent/conversations/{id}/messages**：`[{id, role, content, tool_name?, created_at}]`。

### 3.10 画像与设置

**GET /profile / PUT /profile**：PUT 请求体为 user_profile 表全部业务字段（name/school/major/degree/gpa/english_level/resume_text/target_position/target_city/skills/weaknesses/note）。skills/weaknesses 为逗号分隔字符串。

**GET /settings**：

```json
{"llm_provider":"deepseek","llm_model":"deepseek-flash","llm_base_url":"",
 "tts_enabled":false,"voice_enabled":false,
 "crawl_enabled":false,"crawl_url":"","default_question_count":8,
 "llm_key_set":true,"asr_key_set":false}
```

- `llm_provider` 取值：`deepseek` / `zhipu` / `kimi` / `siliconflow` / `custom`（供应商注册表见系统设计文档 5.4）；
- `llm_model`：所选供应商下的模型 ID（默认 deepseek-flash），候选列表来自 GET /settings/llm-models；
- `llm_base_url`：仅 custom 供应商填写，其余供应商由注册表内置；
- 敏感值不回显，仅以 `*_key_set` 布尔告知前端是否已配置。

**PUT /settings**：可更新上表非只读字段；`llm_api_key/asr_app_id/asr_api_key` 传值则覆盖 config 表，传空串不修改；切换 `llm_provider`/`llm_model` 时旧配置保留（切回即用）。

**GET /settings/llm-models**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| llm_provider | string | 是 | 供应商（同 GET /settings 取值） |
| llm_api_key | string | 否 | 已配置则省略（后端取 config 表），未配置时必填 |
| refresh | bool | 否 | true=强制重拉（默认走 24h 缓存） |

响应：`data:{models:[{id, display_name, is_free}], source:"remote"|"builtin"}`。`source=builtin` 表示拉取失败回退内置模型表（前端标注"内置列表"）。拉取本身失败不报错（仍返回内置表），Key 无效返回 10013。

**POST /settings/llm-test**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| llm_provider | string | 是 | 待测供应商（同 GET 取值） |
| llm_api_key | string | 是 | 待测 Key（不回显，仅本次测试使用） |
| llm_base_url / llm_model | string | 否 | custom 时必填 base_url；model 缺省用注册表默认，候选值从 GET /settings/llm-models 获取 |

行为：向供应商发送一条最小消息验证连通性（不落库、不保存配置）。成功返回 `data:{message:"ok", model:"实际模型名"}`；失败返回错误码 10013，`message` 携带具体原因（Key 无效/网络不通/模型不存在）。

### 3.11 语音（P2）

**POST /asr/transcribe**（multipart，file=音频 ≤2MB，webm/ogg）

响应：`data:{text:"转写文本"}`（失败 60001）。仅转写回填，不落库。
