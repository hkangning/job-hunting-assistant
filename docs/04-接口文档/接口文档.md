## 1. 通用规范

### 1.1 基础约定

- Base URL：`http://localhost:8000/api/v1`（前端开发代理 `/api` → 8000 端口）
- 在线接口文档（FastAPI 自动生成，服务启动后可访问）：Swagger UI `http://localhost:8000/docs`（可交互调试，展开接口 → Try it out → Execute）、ReDoc `http://localhost:8000/redoc`（只读版）
- 数据格式：JSON（UTF-8）；文件上传 `multipart/form-data`；流式接口 `text/event-stream`（SSE）
- 时间格式：`YYYY-MM-DD HH:mm:ss`（本地时间）；日期 `YYYY-MM-DD`
- 分页：请求 `page`（从 1 起）+ `page_size`（默认 10，最大 50）；响应 `data: {total, items}`
- **鉴权**：除白名单 **`POST /auth/register`、`POST /auth/login`、`GET /health`** 三个端点外，**全部接口（含 SSE）均需携带请求头 `Authorization: Bearer <token>`**；Token 由登录/注册接口返回，有效期 = 勾选"30 天免登录"时 30 天、未勾选时 1 天；缺失/无效 → **401 + 80001**，过期 → **401 + 80002**（前端均清本地 Token 跳登录页）
- **数据隔离**：账号私有数据一律按 **Token 对应的登录账号**过滤与写入，请求体/查询参数中**不接受** `user_id`（传入亦忽略）；访问他账号资源一律返回 **404 + 10002**（与"资源不存在"完全一致，不暴露存在性）

### 1.2 统一响应体

```json
{ "code": 0, "message": "ok", "data": {} }
```

`code=0` 成功；非 0 见错误码表。SSE 接口不走此格式。

> **对话链路的四档细分（`llm_client`，步骤 10 起）**：AI 对话调用（JD 分析 / 陪练点评 / 模拟面试 / 面经复盘 / 定时文案）失败时按原因分档——**配置缺失或 Key 无效 → 10012**（引导去 AI 配置页）、**模型不存在或不可用 → 10013**（提示重选模型）、**AI 输出无法解析为 JSON → 10011**（`chat_json` 类调用）、**其余（连接失败 / 超时 / 限流 429 / 服务端 5xx）→ 10010**。重试口径：连接错误 / 超时 / 服务端 5xx 自动重试 1 次，429 与鉴权错**不重试**（立刻反馈，避免放大限流）；流式调用**只重试建流阶段**，已开始输出后中途失败直接按上表报错（已渲染内容保留）。流式接口的失败经 SSE `error` 事件携带同一 `code`（见 1.4）。

> **HTTP 状态码口径**：与 `code` **同源**——后端 `ErrorCode` 枚举以「码 + HTTP 状态码 + 默认文案」三元组绑定（`backend/app/exceptions.py`），上表逐条对齐实现；`70002`（步骤 21）、`70003`（步骤 22）、`40003`（步骤 26）、`60002`（步骤 24）四个码对应的功能尚未实现，状态码按同类码推定，实现时以此表为准。前端**判定一律以响应体 `code` 为准**，HTTP 状态码只服务于网关 / 访问日志 / 监控等中间层——mock 层请照本表取值，不再自行推断。

### 1.4 SSE 事件协议（全部流式接口通用）

```
event: start
data: {"message": "正在分析…"}                       // 连接建立后立即推送（感知延迟优化）

event: delta
data: {"text": "增量片段", "section": "match_score"}   // section 可选，标识报告段落

event: tool_call
data: {"tool_name": "create_application", "args": {...}}  // 仅 Agent 接口

event: done
data: {"record_id": 123, "extra": {...}}                  // 落库 id 与附加数据

event: error
data: {"code": 10010, "message": "..."}                   // 中途失败，已渲染内容保留
```

**实现口径**（协议层统一封装在 `backend/app/utils/sse.py`，各流式接口复用，业务侧只 `yield` 事件、不拼报文）：

| 约定 | 说明 |
|---|---|
| 报文格式 | 每个事件固定 `event: <名>\ndata: <JSON>\n\n`，`data` 为 UTF-8 JSON（中文不转义）；响应头带 `Cache-Control: no-cache` 与 `X-Accel-Buffering: no`（关闭 nginx 缓冲，避免部署到反向代理后事件被攒批） |
| `start` 时机 | **连接建立后立即推送**（进入流式处理的第一件事），先于任何 AI 调用与数据库查询，用于前端即时反馈；实测本机 5~21ms 到达 |
| 事件顺序 | 恒为 `start` → 若干 `delta`（`tool_call` 可穿插）→ `done` 或 `error` 之一收尾；`done` 与 `error` **互斥且不重复** |
| `done` 载荷 | `record_id` 为落库记录 id（不落库的链路为 `null`），`extra` 为链路自定义附加数据（如字数 / 耗时统计）；由业务侧 `return` 提供，协议层统一收口 |
| 数据库会话 | 每个流式请求使用**独立会话**（不复用普通请求的会话），流结束即关闭 |
| 客户端断连 | 后端停止消费上游 AI 流并主动关闭与供应商的连接，**不再推送任何事件**；已渲染内容由前端保留；不视为异常、不记错误日志（仅记一条 INFO 日志便于排查）；**已生成内容按各链路约定收尾**——业务链路通常在自身清理逻辑中落半成品（JD 分析见 §3.6），不落库的链路（如 `/stream/demo`）直接丢弃 |
| 异常分派 | `BizException`（含 AI 链路四档细分，见 §1.3 注）→ 发送其 `code`；其余未预期异常 → 记录堆栈并发送 `10000`。两种情况下 `start` 与已发出的 `delta` **均不撤回** |
| 心跳 / 重连 | **不实现**——首字延迟 < 2s、链路短，且不做 `Last-Event-ID` 续传；断连即结束本次流式请求，前端需重新发起 |

前端因 `EventSource` 不支持 POST，统一使用 `fetch` + `ReadableStream` 手工解析（见系统设计 5.1 / 2.2）。

## 3. 接口详述

### 3.1 通用

**GET /health**

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| - | - | - | - | - |

响应：`{"code":0,"message":"ok","data":{"status":"ok"}}`。**免鉴权**，不含任何账号信息（原 `llm_configured` 字段随多账号改造移除，"是否已配置 AI"改由 `GET /auth/me` 返回，见 §3.2）。

**POST /stream/demo**（**SSE**，流式协议自检，步骤 11 起提供）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| message | string | 是 | 用户输入文本（1~500 字），原样交给当前账号的 AI 配置流式回答 |

- 用途：**开发与联调自检端点，非业务接口**——前端打字机组件（`StreamText`）在业务链路落地前用它联调渲染；测试侧用它做 SSE 协议单测（事件顺序 / 断连 / 异常路径）的靶子；
- 事件流：`start` → `delta`×N → `done`；`done.extra` 携带 `{chars, first_token_ms, elapsed_ms}`（本次输出字数 / 首 token 延迟 / 总耗时），`record_id` 为 `null`（**不落库**）；
- AI 调用走当前账号的 AI 配置（与业务链路同一出口 `llm_client`），失败按 §1.3 注的四档错误码发 `error` 事件（未配置供应商 → 10012）；
- 需携带 `Authorization`；不做业务数据隔离（无业务数据）；
- **入参校验先于流式建立**——`message` 缺失 / 空串 / 超长（>500 字）在进入流式处理**之前**即被拦下，返回的是**普通统一响应体**（`10001`，`Content-Type: application/json`），**不会**产生 `start` 事件或 SSE `error` 事件；其余失败（AI 配置缺失 / 调用失败等）发生在流式处理内，按上述事件流规则以 `error` 事件下发。前端据此区分「请求没发出去」与「流中途失败」两类提示。

### 3.2 账号与鉴权

**POST /auth/register**（**免鉴权**）

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| username | body | string | 是 | 登录名，3~20 位字母/数字/下划线，全站唯一（不区分大小写） |
| password | body | string | 是 | 密码，**≥6 位**（不强制字符类型） |
| nickname | body | string | 否 | 昵称，**≤50 字符**，默认取用户名（提交空串亦取用户名），可在个人中心修改 |
| email | body | string | 否 | 邮箱，**≤100 字符**，填写时校验格式且全站唯一（**不区分大小写**；为后续高级功能预留） |

响应 `data`：`{"token":"<JWT>","expires_at":"2026-09-26 12:00:00","user":{"id":1,"username":"hkn","nickname":"hkn","avatar":null,"role":"ADMIN","plan":"FREE","created_at":"..."}}`

- 注册成功**自动登录**，直接返回 Token（**有效期 1 天**，注册流程不含免登录选项）；
- 注册时自动创建该账号的画像空记录与账号级默认配置（见数据库设计 §4）；**首个注册账号 `role=ADMIN`**，其余 `USER`（本期无权限差异）；
- 用户名重复 → **80003**；邮箱被其他账号占用 → **10003**；密码 <6 位 → **80006**；长度或格式不符 → **10001**。

**POST /auth/login**（**免鉴权**）

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| username | body | string | 是 | 登录名 |
| password | body | string | 是 | 密码 |
| remember_me | body | bool | 否 | 勾选"30 天免登录"传 `true`（默认 `false`） |

响应 `data`：同注册（`token` / `expires_at` / `user`）。`expires_at` 按 `remember_me` 计算：**true = 30 天，false = 1 天**。

- 用户名或密码错误 → **80004**（统一文案，**不区分**用户名是否存在，防枚举）；
- 连续失败 5 次 → 锁定 5 分钟，期间即使密码正确也返回 **80005**（`message` 含剩余锁定时间）；登录成功清零计数并更新 `last_login_at`。

**GET /auth/me**

无参数。响应 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int | 账号 id |
| username | string | 登录名（个人中心只读展示） |
| nickname | string | 昵称 |
| email | string/null | 邮箱 |
| avatar | string/null | 头像相对路径，null = 用默认头像 |
| role | string | `USER` / `ADMIN` |
| plan | string | `FREE` / `PRO`（预留） |
| created_at | datetime | 注册时间 |
| last_login_at | datetime/null | 上次登录时间 |
| **llm_configured** | bool | 当前账号是否已有生效的 AI 供应商配置（false 时概览提示"未配置 AI"） |

**前端启动校验入口**：路由守卫以本接口判断本地 Token 是否仍有效（401 → 80001/80002 → 清本地 Token 跳登录页）。

**PUT /auth/profile**

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| nickname | body | string | 否 | 昵称，**≤50 字符**；传空串或 `null` 表示回退为用户名 |
| email | body | string | 否 | 邮箱，**≤100 字符**；格式校验 + 全站唯一（**不区分大小写**，重复 → 10003）；传空串或 `null` 表示清空 |

响应 `data`：更新后的账号信息（同 `GET /auth/me` 结构）。**用户名不可修改**。

- **部分更新语义**：只更新请求体中出现的字段（未提交的字段保持原值）；`nickname` 提交空串/`null` 回退为用户名，`email` 提交空串/`null` 置空；
- 长度超限 → **10001**；邮箱格式非法 → **10001**；邮箱被其他账号占用 → **10003**。

**PUT /auth/password**

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| old_password | body | string | 是 | 原密码 |
| new_password | body | string | 是 | 新密码，**≥6 位** |

- 原密码错误 → **80007**；新密码 <6 位 → **80006**；
- 成功返回 `data: null`，**当前 Token 立即失效**（含"30 天免登录"的旧 Token，再用旧 Token 请求 → **401 + 80002**）——前端收到成功后清除本地 Token 并跳登录页重新登录。

**POST /auth/avatar**（`multipart/form-data`）

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| file | form-data | file | 是 | 头像图片：jpg / jpeg / png / webp，**≤2MB** |

响应 `data`：`{"avatar":"uploads/avatars/1_a3f9c2d1.png"}`（相对路径，前端拼接后端地址即可直接访问，如 `http://localhost:8000/uploads/avatars/1_a3f9c2d1.png`——后端已把 `uploads/` 挂在 `/uploads` 静态路径下，前端**无需**做路径改写）。

- 前端先压缩为 **256×256** 再上传，后端**仍校验**类型与体积（不符 → 10001），并做兜底处理：Pillow 验真（非图片 → 10001）、最长边 >256 时等比缩放（只缩不放）、jpg/jpeg 且图像模式非 RGB/L 时转 RGB；
- 新头像落盘成功后再更新库并**同步删除旧文件**（同一请求内完成）；上传失败保留原头像。

**DELETE /auth/avatar**：恢复默认头像（删除自定义文件、`avatar` 置空），`data: {"avatar": null}`。

### 3.3 AI 供应商配置

**GET /llm-providers**

无参数。响应 `data`：

```json
{"active":"deepseek",
 "providers":[
   {"provider":"deepseek","name":"DeepSeek","group":"国内",
    "base_url":"https://api.deepseek.com","needs_key":true,"key_set":true,
    "model":"deepseek-flash","is_active":true},
   {"provider":"ollama","name":"Ollama（本地）","group":"本地",
    "base_url":"http://localhost:11434/v1","needs_key":false,"key_set":false,
    "model":"","is_active":false}]}
```

- 返回**注册表全部 12 项**（未配置的也在列表中，供前端渲染卡片），`group` 取值：国内 / 国外 / 聚合 / 本地 / 自定义；
- `needs_key` 为该供应商**是否需要 API Key**（注册表静态属性，`ollama` 本地部署为 `false`、其余 11 家为 `true`）。前端据此判断「免 Key 供应商」（免 Key 项无 Key 也可保存 / 激活 / 拉模型），**不要按供应商标识硬编码**——注册表新增免 Key 项时硬编码会静默失配；
- `key_set` 仅表示当前账号在该供应商下**是否已存 Key**（**永不回显明文或片段**）；`needs_key=false` 的供应商 `key_set` 恒为 false 且不影响使用；
- `model` 为该账号在该供应商下所选模型，**未选择时为空串 `""`**（= 用注册表默认模型）；`active` 为当前生效供应商标识（无则 null）。

**PUT /llm-providers/{provider}**

`provider` 为注册表标识之一（非法 → 10001）。

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| api_key | body | string | 否 | 密钥；**省略或留空 = 不修改已存 Key**（首次配置必填；`needs_key=false` 的供应商可空）；**传新值时旧模型缓存一并作废**（换 Key 后重新拉取，避免命中旧缓存掩盖无效 Key）；入库前 Fernet 加密 |
| base_url | body | string | 否 | 覆盖注册表默认端点（应对端点变更）；传空串 = 恢复默认 |
| model | body | string | 否 | 该供应商下所选模型 ID（候选来自模型列表接口）；传空串 = 用注册表默认模型 |

响应 `data`：该供应商的配置项（结构同 GET 列表中的单条）。约束：每账号每供应商一行（`user_id + provider` 唯一），重复保存走更新；**保存不改变当前激活项**（激活见下）；**首个保存的供应商自动生效**（账号尚无激活行时，见数据库设计 3.17）；`custom` 未填端点 → 10001。

**DELETE /llm-providers/{provider}**

删除当前账号在该供应商下的全部配置（Key / base_url / model / 模型缓存），`data: null`。**仅影响该供应商**，其余不受影响。

- 该供应商**尚未配置**（无配置行）→ **10002**；

- 若删除的是**当前激活项**，`active` 变为 null，AI 功能进入"未配置"状态（后续 LLM 调用返回 10012），前端须二次确认后提交。

**POST /llm-providers/{provider}/activate**

无请求体。把该供应商置为**当前生效**（同一事务内取消该账号其他行的激活位，保证至多一行生效），`data: {"active":"deepseek"}`。

- 切换后**立即生效**，无需重启、无需重填 Key（已存配置保留，切回即用）；
- 该供应商尚未配置 Key（`key_set=false` 且 `needs_key=true`）→ 10001，提示先填写并保存 Key。

**GET /llm-providers/{provider}/models**

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| refresh | query | bool | 否 | `true` = 强制重拉（默认走 24h 缓存） |
| api_key | query | string | 否 | **临时探测**的 Key（**不落库**）；省略或留空 = 用当前账号已存 Key |
| base_url | query | string | 否 | **临时探测**的端点（`custom` 必填，其余可省略）；省略或留空 = 用账号已存端点 / 注册表默认值 |

响应 `data`：`{"models":[{"id":"glm-4.7-flash","display_name":"GLM-4.7 Flash"}],"source":"remote","fetched_at":"2026-09-25 12:00:00"}`

- **传 `api_key` 或 `base_url` = 临时探测**（与 `POST /llm-providers/test` 同口径）：**不读缓存、不写缓存、不落库**，供「Key / 端点已填、尚未保存」时先看有哪些模型可选——结果属于「未保存的配置」，若写进缓存会污染已存 Key 的模型列表。**已保存的配置无需传参**（传了会绕过 24h 缓存、每次实时拉取）；
- 两个参数**均不传**时：Key 取**当前账号已存配置**；结果缓存 24h（存 `llm_provider_config.models_cache`，按 provider + base_url 维度）；**未保存过配置的供应商无处落缓存，每次实时拉取**；
- 未传 `api_key` 且该供应商**未配置 Key**（`key_set=false` 且 `needs_key=true`）→ **不报错，回退内置模型表**（`source="builtin"`）——供应商的 `GET /models` 需鉴权、无 Key 拿不到实时列表，故给内置清单，**选完供应商即可先看到可选模型**；填 Key 保存后再拉取即得全量实时列表（**保存配置、连通性测试、激活仍强制填 Key**，此处放宽只为预览，不代表可以免 Key 使用 AI 能力）。**例外**：**自定义供应商且传了 `base_url`**——自建端点是否需要 Key 由端点本身决定（本地 LM Studio / vLLM / 内网网关通常不校验），注册表静态属性判不了，故无 Key 时以占位值发出请求；端点确实要求鉴权则回 **10013**；
- 未传 `base_url` 且 `custom` 未填端点 → 10001；
- `source="builtin"` = **内置模型表**（`fetched_at` 为 `null`，非缓存结果），两种来源均**不报错**：①**未配 Key** 的预览清单（前端标注"内置清单（填写 Key 后拉取完整列表）"）；②**拉取失败**（网络不通等非鉴权类失败的回退，前端标注"内置列表（上次拉取失败）"）；
- 已存 Key 或传入的临时 Key 无效 → **10013**（鉴权类失败**不回退**内置表，否则会掩盖 Key 配置错误）；
- 远程拉到的模型**跨供应商查内置模型表**补展示信息——模型 ID 全局唯一，经聚合 / 自定义供应商调用的已知模型（如 `glm-4.7-flash`）同样能拿到中文展示名；内置表未记载的新模型以 ID 原样展示。

**POST /llm-providers/test**

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| provider | body | string | 是 | 待测供应商（注册表标识） |
| api_key | body | string | 否 | 待测 Key；**省略则用当前账号已存 Key**（均不落库、不改配置） |
| base_url | body | string | 否 | 同 PUT 语义（`custom` 必填） |
| model | body | string | 否 | 待测模型，缺省用注册表默认 |

行为：向供应商发送一条最小消息验证连通性（**不落库、不保存配置**）。成功 `data: {"message":"ok","model":"实际模型名"}`；失败 **10013**，`message` 携带具体原因（Key 无效 / 网络不通 / 模型不存在）；`provider` 非法 → **10001**，未配置 Key 且请求未传 → **10012**（**与 `models` 的免 Key 豁免同口径、但不回退内置表**：自定义供应商传了 `base_url` 时以占位值试连，端点真要鉴权则回 10013；其余供应商缺 Key 直接 10012 引导去填——连通性测试测的就是 Key 与端点，缺 Key 测不出所以然）。

> `api_key` / `base_url` 的取值口径与 `GET /llm-providers/{provider}/models` 的**临时探测参数**一致（传值优先、省略用已存配置）——两个探测接口同口径，前端可统一按「表单当前值优先、留空回落到已存配置」构造请求。

### 3.6 JD 匹配分析

**POST /stream/jd-analysis**（SSE）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| jd_text | string | 是 | JD 原文（≤10000 字） |
| application_id | int | 否 | 关联投递记录 |

事件流：`delta`（section 依次为 `match_score/scores/strengths/gaps/advice`）→ `done`（`record_id` = jd_analysis_report.id；`extra` 恒为 `null`）。用户中途断开：已生成内容落库并标记为**未完成**（`is_finished=false`）。

**实现口径**：

| 约定 | 说明 |
|---|---|
| 校验先于流式建立 | `application_id` 不存在或非本人所有 → **404 + 10002**；`jd_text` 为空或超 10000 字 → **400 + 10001**。两类校验都在流式响应建立**之前**完成，按**普通响应体**返回，不产生 SSE 事件 |
| 画像为空 | **不阻塞**：画像未填写时照常分析，prompt 中标注「尚未填写画像」，由 AI 改按 JD 自身与常见岗位要求判断 |
| `section` 语义 | 仅为**段落锚点**，供前端分段定位/折叠；段落标题行本身**随 `delta` 原样下发**，故 `report_text` 恒等于全部 `delta` 的拼接（含标题行）。AI 输出未按模板给出标题时**沿用当前 `section`**；全程识别不出标题则不下发 `section` 字段（纯文本降级，前端按无锚点渲染） |
| `score` 提取 | 从报告文本匹配「综合匹配度：XX」——兼容全角/半角冒号与 markdown 加粗；取不到或不在 0~100 范围记为 `null` |
| 中途失败 | 发 `error` 事件（AI 链路四档见 §1.3 注），**不落库**：失败报告不保留，前端重新发起即重跑 |
| 客户端断开 | 与"失败"不同——已生成内容**原样落库**并标记 **`is_finished=false`**（落库文本 = 断开前已下发的全部 `delta` 拼接，与完整报告同一口径，前端无需二次处理）；前端**据此识别「未完成」**，不再用 `score` 是否为空推断（断点落在评分行**之后**时 `score` 已有值、判据失效）；前端重新发起即再次分析，一条内容都没生成时不落库 |

**GET /jd-reports**（query：application_id 可选、page、page_size）

items：`[{id, application_id, company, score, is_finished, created_at}]`（company 取自关联投递联表，未关联或投递已不存在时为 `null`）。

- 排序：按生成时间 `created_at` 倒序，同一秒内按 `id` 倒序（新旧稳定可辨）；
- 分页：`page` 从 1 起，`page_size` 默认 **10、最大 50**（越界 → 10001）；
- `application_id` 筛选只在本账号记录内匹配，查无结果返回空列表（不报错）。

**GET /jd-reports/{id}**：`data:{id, application_id, jd_text, report_text, score, is_finished, created_at}`。不存在或不属于当前账号 → **404 + 10002**（两种情形均返回同一错误码，不可区分）。

**字段说明**：`is_finished` —— 报告是否完整生成：`true` 正常完成 / `false` 客户端断连的半成品（**内容不全**）。列表项与详情均返回该字段，前端据此显示「未完成」标记（**不要**改用 `score` 是否为空推断）。

| qtypes | array | 否 | 题型数组，元素 `SUBJECTIVE`/`CHOICE`/`SCENARIO`；不传 = 不限题型 |
| count | int | 否 | 抽题数，默认 1，最大 5 |

- 三个筛选条件为**与**关系：栈限定范围、领域进一步细化、题型再收窄；全部不传即全库随机；
- 命中题目不足 `count` 时按实际数量返回（不报错）。

响应：`data:{items:[{id, stack, direction, content, qtype}]}`。注意：**不含 answer**（防止先看答案）；`SCENARIO` 题的 `rubric` 同样不下发。

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|

|---|---|


### 3.13 语音（P2）

模拟面试与练习模式的长时长语音交互由**前端 VAD 断句 + 逐句调用转写**实现：前端 VAD 按当前语速**自适应判定静音阈值**（快 1.6s / 正常 2.65s / 慢 3.6s），切出 3~15s 片段即上传，转写文本**累积回填**到作答框，用户全程连续说话、整场不限轮次与总时长。播报侧由后端合成音频返回，前端 `<audio>` 播放、可随时打断。

**POST /asr/transcribe**（multipart：`file`=音频片段，webm/ogg/wav，单片段 ≤2MB）

响应：`data:{text:"转写文本",duration_ms:1200}`（失败 **60001**）。仅转写回填，**不落库**。

- 供应商由账号的 `asr_provider` 决定：`funasr` 走**本地流式模型**（进程内推理，不出网，首次调用需加载模型故首句略慢）；`xunfei` 走云端接口（需已配 Key，未配 → 60001）；
- 单次请求对应**一个语音片段**而非整场录音——长时长的实现方式，故服务端不限制轮次与累计时长。

**分句时间轴（`segments`）约定**：VAD 在前端执行，**句间停顿只有前端知道**——前端在**提交作答**时（`/stream/interview-chat` 或 `/stream/drill-review`，见 §3.7 / §3.15）须一并上传 `segments`：`[{seq, start_ms, end_ms, text}]`（每句序号、起止毫秒、该句原始转写文本）。后端据此计算语速 / 填充词密度 / 停顿点 / 有效时长占比 / 流畅度趋势五项表达力指标（口径见 SRS §3.11、设计见系统设计 5.7）。**该字段是表达维度的唯一数据来源**——不传则本次作答只出内容点评、不出表达点评；`POST /asr/transcribe` 接口本身不变（仍只做单片段转写、不落库）。

**POST /tts/synthesize**

```json
{"text":"这道题可以从三个层面回答","voice":"zh-CN-XiaoxiaoNeural"}
```

- `voice` 可省略，缺省用账号的 `tts_voice` 配置；
- 响应：**音频流**（`audio/mpeg`，直接作为 `<audio src>` 播放），**不走统一响应体**；
- 失败 → **标准响应体 + 60002**（前端静默降级，该句不播报）；
- 服务端按 `sha1(text + voice)` 缓存合成结果（`backend/cache/tts/`），同一文案 + 同一音色**只合成一次**；命中缓存直接返回。

**GET /tts/voices**：返回可选音色列表 `data:[{id:"zh-CN-XiaoxiaoNeural",name:"晓晓",gender:"Female",style:"温暖亲和"},...]`，供设置页下拉选择（默认音色置顶）。

### 3.15 练习模式（FR-020，P2）

同一道题反复练的练习形态，与模拟面试**共用转写、表达力指标与点评底座**（见系统设计 5.7）。**路径前缀为 `/drills`**——项目内 `practice` 专指八股陪练（§3.8），两者不可混用。

**GET /drills**（query：`archived` 可选 bool、`source` 可选、`page`、`page_size`；**默认只返回未归档**）

items：`[{id, title, source, ref_id, archived, attempt_count, last_score, best_score, created_at, updated_at}]`——`attempt_count` / `last_score` / `best_score` 为聚合字段，供列表页直接展示进度概况。

**POST /drills**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| title | string | 是 | 题目标题（≤50 字） |
| question | string | 否 | 完整题面；不传则由 AI 按 `title` + 来源生成 |
| source | string | 否 | 来源枚举（见 SRS §4.1），默认 `CUSTOM` |
| ref_id | int | 条件必填 | `source` 非 `CUSTOM` 时必填（来源实体 id）；后端校验归属，不属于当前账号 → 10002 |

响应：`data = topic DTO`。**只记来源不复制内容**——`ref_id` 用于回跳与标注，题面以本次写入的 `question` 为准。

**GET /drills/{topic_id}**：topic DTO + `attempts` 摘要数组：

```json
{"id":1,"title":"自我介绍","question":"...","source":"INTRO","ref_id":null,
 "archived":0,"created_at":"...","updated_at":"...",
 "attempts":[{"id":9,"seq":3,"is_voice":1,"score":8,"duration_ms":68000,"created_at":"..."}]}
```

`attempts` 摘要**不含点评全文与指标**（控制体量），完整内容走单次详情接口。

**PUT /drills/{topic_id}**：部分更新语义（只更新请求体中出现的字段）——`title` / `question` / `archived`（`true` 归档、`false` 恢复）。归档后：默认列表不展示、**不可再提交作答**（→ 40003），历史记录仍可查看。

**GET /drills/{topic_id}/attempts/{attempt_id}**：单次练习完整 DTO：

```json
{"id":9,"topic_id":1,"seq":3,"answer":"...","is_voice":1,"voice_metrics":{...},
 "score":8,"review":"...","duration_ms":68000,"created_at":"..."}
```

`voice_metrics` 结构见数据库设计 §3.19；非语音作答或作答过短为 `null`。

**GET /drills/{topic_id}/progress**：跨次进步对比。

```json
{"topic_id":1,"attempt_count":3,
 "items":[{"seq":1,"score":5,"duration_ms":95000,"speech_rate":210,"filler_count":12,"pause_count":3,"speech_ratio":0.71},
          {"seq":3,"score":8,"duration_ms":68000,"speech_rate":235,"filler_count":4,"pause_count":1,"speech_ratio":0.85}],
 "deltas":{"score":3,"duration_ms":-27000,"filler_count":-8,"pause_count":-2}}
```

- `items` 按 `seq` 升序给出全部记录，供前端画趋势线；
- `deltas` 为**最近一次 vs 上一次**；练满 **2 遍**才返回（首遍无对比对象，`deltas` 为 `null`）；
- **口径版本不一致的记录不参与对比**（`voice_metrics.version` 不同即跳过——宁可少展示一次对比，也不给出失真曲线，见系统设计 5.7）；文字作答的记录表达指标为 `null`，不参与表达指标对比。

**POST /stream/drill-review**（SSE）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| topic_id | int | 是 | 题目 id（须属于当前账号且未归档，归档 → 40003） |
| answer | string | 是 | 本次作答文本 |
| is_voice | bool | 否 | 默认 false |
| segments | array | 否 | **语音作答时必传**：分句时间轴（格式同 §3.7），供计算表达力指标 |
| duration_ms | int | 否 | 作答耗时（毫秒），前端计时上报 |

事件流：`start`（"正在点评…"）→ `delta`（section 依次 `score` / `review`）→ `done`（`record_id` = 新 drill_attempt.id，含 `seq`；语音作答且已算出指标时 `extra:{voice_metrics:{...}}`）。

- **表达力指标先于点评返回**：指标由纯函数在落库前算出（毫秒级、零 token），随 `done` 一次性下发，前端先展示指标、再等点评流完；
- 点评中的知识点与模拟面试同口径提示入错题本候选（`source_type=DRILL`，用户确认后经 `POST /wrong-questions` 入本，见 §3.9）。

|---|---|---|---|---|

| job_type | query | string | 否 | `CAMPUS` / `INTERN` / `SOCIAL` |
| keyword | query | string | 否 | 岗位名 / 公司名模糊匹配 |
| status | query | string | 否 | 默认只返回 `ACTIVE`（`CHANGED` 随 `ACTIVE` 一同返回） |
| sort | query | string | 否 | `time`（默认，按 `first_seen_at` 降序）/ `match`（匹配度降序） |
| page / page_size | query | int | 否 | 默认 1 / 10 |

items：`[{id, title, company, city, edu_req, major_req, salary_text, job_type, deadline, source_site, source_url, ingest_source, status, first_seen_at, changed_at, match_score, is_applied}]`

- **结果 = 公共岗位（`user_id=0`）+ 本账号投喂的岗位**，其他账号的投喂记录**完全不可见**（跨账号隔离必测）；
- `is_applied` 按「公司 + 岗位名」比对**当前账号**的投递记录得出，供卡片显示"已投递"（见 SRS §3.18 业务打通）；
- `ingest_source` 区分 `AUTO` 自动抓取 / `FEED` 投喂——**投喂记录才有 `raw_excerpt`（原文摘录）**，自动抓取**不存正文**（NFR-016）。

**POST /job-postings/ingest**（投喂：抽取预览，**不入库**）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| text | string | 条件必填 | 粘贴的 JD 原文（与 `url` 二选一，**同传 → 10001**） |
| url | string | 条件必填 | 招聘信息链接（走合规抓取：UA 标识 / 同域限频 / **拒绝内网地址**，见系统设计第 6 章） |

响应 `data`：`{fields: {...岗位字段...}, missing: ["deadline","city"], source: "FEED", fetched_from: "url"}`

- `fields` 为 AI 抽取的结构化结果，`missing` 列出**未抽取到的字段**（前端标黄提示用户补充）；
- **本接口只返回预览、不落库**——用户确认后调用 `POST /job-postings` 入库（与 Agent 写操作出确认卡片同口径）；
- 抽取失败（LLM 输出不可解析）→ **70003**；链接需登录 / 被站点拒绝 / 内网地址 → **70003**（message 区分两类原因），前端提示并降级为手动填表。

**POST /job-postings**（确认入库）

请求体：岗位字段（`title` / `company` 必填，其余同列表字段，`raw_excerpt` 可回传原文供日后校对）。`user_id` / `dedup_key` / `ingest_source` 由服务端生成（`ingest_source=FEED`）。响应 `data = 岗位 DTO`。

- 同一账号内重复投喂（`UNIQUE(user_id, dedup_key)` 命中）→ 覆盖更新，不报错。

**DELETE /job-postings/{id}**：删除投喂岗位。**自动抓取的岗位不可删 → 10001**；不存在或非本账号 → 10002（不可区分，见系统设计 3.6）。

**GET /crawl-sources**（源清单）

items：`[{id, school_name, system_type, domain, params, enabled, last_crawl_at, last_status, last_error}]`

- `system_type` 为 `91JOB` / `BYSJY`（云就业）/ `JYSD`（才立方）；`params` 为该系统所需参数的 JSON 对象（如 `{"menu_id": 123}` / `{"universityid": 456}`）；
- `last_status` 为 `OK` / `FAILED`（源疑似失效）/ `BLOCKED`（robots 禁止或持续 403，**已停止该源不重试**）/ `null`（从未抓取）；`last_error` 为失败原因摘要。

**POST /crawl-sources**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| school_name | string | 是 | 学校名称（≤100 字） |
| system_type | string | 是 | `91JOB` / `BYSJY` / `JYSD`，非法值 → 10001 |
| domain | string | 是 | 站点域名（仅 http/https） |
| params | object | 否 | 系统参数（按 `system_type` 取值） |

- 同一系统 + 同一域名重复登记 → **10003**；
- **新增一所学校 = 加一行配置，不写代码**。

**PUT /crawl-sources/{id}**：部分更新 `school_name` / `domain` / `params` / `enabled`；改 `system_type` 不支持（需删除后重建）→ 10001。

**DELETE /crawl-sources/{id}**：删除源。**已抓到的条目保留**（不连带删除，见数据库设计 3.20）。

**POST /crawl-sources/run**（手动触发采集，演示用）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| source_id | int | 否 | 指定单个源；不传 = 执行全部启用中的源 |

响应 `data`：`{total, ok, failed, blocked, items_new, items_updated, items_changed, expired, details: [{source_id, school_name, status, error, counts}]}`

- **单源失败不整体报错**——逐源结果计入 `details`，整体仍返回 200；**指定 `source_id` 且该源失败 → 502 + 70002**（单源粒度才报错，便于调试）；
- 执行完成后按新入库 / 变更的条目对全部账号跑一遍订阅匹配。

**GET /calendar**（日历事件聚合，FR-022）

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| start | query | date | 是 | 区间起（含） |
| end | query | date | 是 | 区间止（含）；`end < start` → 10001 |

响应 `data`：`[{event_type, title, event_at, ref_type, ref_id, company, location, status}]`——**一次请求返回四类事件**，前端不再并发拉两个列表：

| event_type | 数据来源 | 说明 |
|---|---|---|
| `TALK` / `FAIR` | `campus_event`（`event_date` 落在区间内） | 宣讲会 / 双选会 |
| `EXAM` | 当前账号 `application.next_event_at`，且 `status=WRITTEN` | 笔试 |
| `INTERVIEW` | 当前账号 `application.next_event_at`，且 `status=INTERVIEW` | 面试 |

- `ref_type` 为 `campus_event` / `application`，与 `ref_id` 一起供前端点击跳转；
- 空区间返回**空数组**，不报错；跨月查询按 `start`/`end` 区间取（前端按整月下发）。

**GET /subscriptions**（订阅规则列表）：items `[{id, name, keywords, companies, cities, info_types, enabled, created_at}]`——数组类字段直接返回**数组**（库中为 JSON 字符串，接口层转换）。

**POST /subscriptions**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | 是 | 规则名称（≤50 字） |
| keywords | array | 否 | 关键词数组（命中标题 / 公司名） |
| companies | array | 否 | 公司名数组 |
| cities | array | 否 | 城市数组（岗位按城市、宣讲会按地点文本） |
| info_types | array | 否 | `TALK` / `FAIR` / `JOB`，空 = 不限 |
| enabled | bool | 否 | 默认 `true` |

**匹配语义**：字段留空 = 该维度不限；**不同维度之间 AND、同一维度数组内部 OR**。规则命中后写站内提醒（`reminder_type=INFO_MATCH`，同一条信息同日不重复提醒）。

**PUT /subscriptions/{id}** / **DELETE /subscriptions/{id}**：修改（含 `enabled` 开关）/ 删除；不存在或非本账号 → 10002。
