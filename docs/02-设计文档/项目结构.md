## 1. 仓库与分支形态

**远端仓库**：`https://github.com/hkangning/job-hunting-assistant`

协作采用**分支隔离**：两人各用一份本地工作目录，各自 checkout 自己的分支，代码直接写在**该分支的仓库根目录**下。

| 分支 | 承担内容 | 代码落位（仓库根下） | 负责人 |
|---|---|---|---|
| `docs` | **公共文件唯一权威源**（文档与仓库配置） | `docs/`、`README.md`、`.gitignore` | 胡康宁 |
| `backend` | 后端全部代码（FastAPI） | `app/`、`tests/`、`requirements.txt`、`pytest.ini`、`.env.example`、`seed/` | 胡康宁 |
| `frontend` | 前端全部代码（Vue 3 + Vite） | `src/`、`package.json`、`vite.config.js`、`index.html` | 卢世君 |
| `main` | 三端汇合分支 | 上述文件在根目录并列 | — |

**公共文件**（`docs/`、`README.md`、`.gitignore`）以 **`docs` 分支为唯一权威源**；`backend`、`frontend` 分支各持一份副本供开发查阅，**不直接编辑**。变更流程：

1. 在 `docs` 分支工作目录（`git worktree` 独立检出，与 backend 共用同一仓库）修改并提交；
2. 推送 `origin/docs`；
3. 同步两个分支：各目录 `git fetch origin` 后执行 `git checkout origin/docs -- docs README.md .gitignore`，提交推送；
4. **禁止**在 `backend`/`frontend` 分支直接修改公共文件，防止三份副本分叉。

**各分支独有文件（合并时自动并存，无需同步）**：后端 `.env.example`、`pytest.ini`、`requirements.txt`；前端 `package.json`、`package-lock.json`、`vite.config.js`、`index.html`。不入库：`.venv/`、`node_modules/`、`*.db`、`dist/`、`.env`（真实密钥）。

> 目录树阅读说明：第 2、3 节的 `backend/`、`frontend/` 是**分支代称**（代表"该分支的仓库根"），不是仓库根下的子目录；`docs/` 与 `README.md` 在每个分支都完整存在。

## 4. 命名与编码约定

| 项 | 约定 |
|---|---|
| Python | PEP 8；模块 snake_case、类 PascalCase；routers/services 内函数与接口语义同名（`create_application` 等） |
| Vue | 组件 PascalCase 文件名；组合式 API（`<script setup>`）；页面组件命名与路由一致 |
| DTO | Pydantic 模型每字段中文注释（含枚举取值），与接口文档字段表一一对应 |
| 枚举 | 单一定义在 `app/models/enums.py`，DB 存 VARCHAR 码，DTO 层做 str/enum 转换 |
| 错误码 | 只允许在 `app/exceptions.py` 定义，与接口文档错误码表一致，禁止散落魔法数字 |
| 提交规范 | 一次提交对应一个文档或一个功能步骤；message 用中文概述 |
