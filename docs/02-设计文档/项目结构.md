## 1. 仓库与分支形态

**远端仓库**：`https://github.com/hkangning/job-hunting-assistant`

采用**单仓库 + 分支隔离**：仓库根下三个平级子目录 `docs/`、`backend/`、`frontend/`；两人各用一份本地工作目录，各自 checkout 自己的分支，代码写在自己负责的子目录内。

| 分支 | 承担内容 | 代码落位（仓库根下） | 负责人 |
|---|---|---|---|
| `backend` | 后端代码 + 公共文件副本 | `backend/`（后端全部文件）、`docs/`、`README.md`、`.gitignore` | 胡康宁 |
| `frontend` | 前端代码 + 公共文件副本 | `frontend/`（前端全部文件）、`docs/`、`README.md`、`.gitignore` | 卢世君 |
| `main` | 汇合分支（三目录齐全，可运行完整系统） | `docs/`、`backend/`、`frontend/` | — |

**职责边界**：两人各管一摊，**不越界改动对方范围内的内容**。

| 负责人 | 负责范围 |
|---|---|
| 胡康宁（后端） | `backend/` 全部代码、数据库设计；文档中**除前端 / 测试外**的章节（后端 / 数据库 / 共性内容） |
| 卢世君（前端 + 测试） | `frontend/` 全部代码、测试工作；文档中**前端 / 测试相关**的章节 |

后端侧**不主动改动**下列内容，需变更时知会对方、由对方执行：

- `frontend/` 下任何文件（含 `package.json`、`package-lock.json`、`.npmrc`、构建配置）；
- 测试相关：`backend/tests/` 内容、测试计划、测试日志；
- 前端 / 测试专属文档内容：前端工作日志、问题记录，及本文档中的前端目录树、前端依赖清单、前端启动等章节。

反向同理：前端侧不主动改动 `backend/` 下的后端代码与数据库相关文档章节。

**公共文件**（`docs/`、`README.md`、`.gitignore`）在 `backend`、`frontend` 两条分支上**各持一份**，任一侧改后需**相互拉取**同步（只取公共文件，不带对方代码）：

```bash
git fetch origin
git checkout origin/<对方分支> -- docs README.md .gitignore
git add -A && git commit -m "文档同步：<变更内容>"
git push origin <自己分支>
```

改公共文件前先知会对方；两侧副本内容保持一致（git 入库均为 LF，工作区行尾差异不影响）。

**各分支独有文件天然分属不同子目录**（`backend/`、`frontend/`），合并时自动并存，无需同步。不入库：`backend/.venv/`、`frontend/node_modules/`、`*.db`、`frontend/dist/`、`.env`（真实密钥）。

**跨职责文件区**：`backend/tests/` 在目录上归 `backend/`，但测试代码**内容**由测试负责人（卢世君）维护——**目录归属与内容归属不同**。约定：

- 测试侧改动此目录前，先 `git fetch origin` 取后端侧最新版再叠加，**不基于本地旧版重写**；
- 后端侧因修 fixture、补测试隔离逻辑等需改动此目录时，**改前先知会测试侧**；
- 该目录的合并冲突**以后的版本为准**（与公共文件同口径）。

依据：2026-09-24 `conftest.py` 在合并中被拼成两套测试库隔离方案并存，`import` 丢失致测试全线失败（见[问题记录](../07-工作日志/问题记录.md) IS-09 / IS-13）。

**问题记录**：`docs/07-工作日志/问题记录.md` 虽位于 `docs/` 下（属公共文件），但**内容由测试负责人（卢世君）统一维护**，后端侧**不主动修改**。约定：

- 后端侧发现问题时，先记入[后端工作日志](../07-工作日志/后端工作日志.md)并知会测试负责人，由对方分配编号（`IS-XX`）登记进问题记录；
- 后端侧引用问题记录时**只读**；确需修改时先知会测试侧，由对方执行。

**合入 main**：两分支都稳定后，在任一工作目录执行 `git checkout main && git merge backend && git merge frontend && git push origin main`。

## 4. 命名与编码约定

| 项 | 约定 |
|---|---|
| Python | PEP 8；模块 snake_case、类 PascalCase；routers/services 内函数与接口语义同名（`create_application` 等） |
| Vue | 组件 PascalCase 文件名；组合式 API（`<script setup>`）；页面组件命名与路由一致 |
| DTO | Pydantic 模型每字段中文注释（含枚举取值），与接口文档字段表一一对应 |
| 枚举 | 单一定义在 `app/models/enums.py`，DB 存 VARCHAR 码，DTO 层做 str/enum 转换 |
| 错误码 | 只允许在 `app/exceptions.py` 定义，与接口文档错误码表一致，禁止散落魔法数字 |
| 鉴权 | 账号私有接口一律经 `Depends(get_current_user)` 取 `user_id`，**不接受请求体 / 查询参数传入的 user_id**；公共接口（health、注册、登录）显式豁免 |
| 提交规范 | 一次提交对应一个文档或一个功能步骤；message 用中文概述 |
