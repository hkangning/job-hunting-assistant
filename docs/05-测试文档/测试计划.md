## 1. 测试策略

### 1.1 总原则

- **LLM 调用 100% mock**：测试离线可跑、不产生 API 调用费用、结果确定（SRS NFR-012）。真实供应商联调用**一次手动冒烟**验证（见 5.1），不入自动化；
- 测试金字塔：服务层单元测试 > API 集成测试 > 前端手工验收；SSE 流式链路有专项集成测试；
- 测试数据库用**临时目录下的独立 SQLite 文件**，不碰开发库。具体方式：`conftest.py` 模块级以 `tempfile.mkdtemp()` 建临时目录（必须在任何 `app.*` 导入之前设置 `DATABASE_URL`，此时 fixture 尚不存在）；fixture 作用域内可按需改用 `tmp_path`。

### 1.2 工具与框架

| 项 | 选型 |
|---|---|
| 测试框架 | pytest + pytest-asyncio |
| API 测试 | FastAPI TestClient（依赖注入替换 LLM） |
| Mock | `FakeLLMProvider` / `FakeASR` / `FakeTts`（见下）；测试期不启用定时调度器 |
| 覆盖率 | pytest-cov，目标：services 层 ≥ 80% |

### 1.3 LLM Mock 方案

`app/clients/llm_provider.py` 定义抽象 `LLMProvider`，生产实现走 DeepSeek。测试 `conftest.py` 注入 `FakeLLMProvider`：

- `stream_chat()` 返回**预设 token 序列**（按场景预置：JD 五段报告、面试点评+下一题、八股点评等），可断言落库内容；
- `chat_json()` 返回预设 dict（面经条目/错题判定）；
- `list_models()` 返回预设模型列表（或 `fail=True` 模拟拉取失败，验证回退内置表路径，见 TC-49）；
- 可配置 `fail=True` 模拟 LLM 异常，验证兜底路径（错误码 10010/10011/40002）；
- 可配置 `delay=0.001` 模拟流式节奏，验证 SSE 事件顺序。

**注入方式**：`app.main` 的依赖容器（`get_llm_provider`），TestClient 覆盖依赖即可，生产代码零改动。

**语音 Mock 方案**（P2，对应系统设计 5.6）：`FakeASR` 返回预设转写文本（可配 `fail=True` 验证 60001 不阻塞流程）；`FakeTts` 返回固定 mp3 字节流、不加载 FunASR 模型、不调 edge-tts。**语音测试不触网、不加载本地模型**——FunASR 模型数百 MB 且首次需联网下载，测试中加载既慢又不可离线复现。

## 5. 联调与冒烟（一次性，手动）

### 5.1 真实供应商冒烟（默认 DeepSeek，配置 .env 或设置页后）

### 5.2 语音链路冒烟（P2 开发后）

1. **ASR**：启动后端（FunASR 本地模型首次需联网下载，此后离线可用）→ 连续说话 1 分钟以上、其间多次停顿 → 确认静音自动断句、逐句转写文本正确且每句 **<1.5s**（NFR-002，本地模型实测约 600ms 出字）；
2. **断网复测**：断开外网重跑第 1 步，确认识别仍可用（本地模型不出网）；
3. **TTS**：`POST /tts/synthesize` 合成一段文本 → 返回 mp3 可播放；设置页切换音色后重新合成，**音色即时变化**；同一文本二次合成**命中 sha1 缓存**（响应明显更快、不重复调 edge-tts）。
