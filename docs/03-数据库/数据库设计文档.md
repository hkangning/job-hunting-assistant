## 1. 设计约定

| 项 | 约定 |
|---|---|
| 数据库 | SQLite 3，单文件 `app.db`，启用 WAL 模式与外键（`PRAGMA foreign_keys=ON`，连接级设置） |
| 命名 | 表名/字段名全小写下划线（snake_case）；表名单数；关联外键 `xxx_id` |
| 主键 | 除 config 表外全部 `id INTEGER PRIMARY KEY AUTOINCREMENT`；config 为 `(user_id, key)` 联合主键 |
| **账号归属** | **账号私有表**均含 `user_id INTEGER NOT NULL, FK→user.id`，并建 `idx_<表名>_user` 索引；**子表**（interview_qa / experience_item / agent_message）**不冗余存 `user_id`**，经父表间接隔离；**公共表**（question / campus_event）不含 `user_id`，全站共享。归属划分见 §2 |
| 时间字段 | 一律存**本地时间**（datetime），Python `datetime` 对象直存；日期判定用 `date()` 比较 |
| 时间戳字段 | 每张业务表含 `created_at`；可更新表含 `updated_at`（应用层维护，不用触发器） |
| 枚举 | 以 VARCHAR 存**大写英文码**（如 `APPLIED`），Python 侧用 `enum.Enum` 映射，口径见第 5 章 |
| 软删除 | 不引入——删除即物理删除（本机使用场景，看板删除已有二次确认） |
| JSON 字段 | 少量动态结构（Agent 工具参数、模型列表缓存）以 TEXT 存 JSON 字符串，应用层序列化，不建 JSON 查询 |
| 索引 | 只建查询路径上的索引（见各表），不在全表数百行的规模上过度索引 |
| 加密字段 | `llm_provider_config.api_key`、`config` 中的讯飞 ASR 凭据（`asr_api_key`）以 **Fernet 对称加密**后存 TEXT（主密钥 `APP_SECRET_KEY` 在 .env）；**默认的 FunASR 本地模型与 edge-tts 不需要任何凭据，故无字段** |

## 2. ER 关系总览

```mermaid
erDiagram
    user ||--|| user_profile : "每账号一份画像"
    user ||--o{ llm_provider_config : "每账号每供应商一行"
    user ||--o{ application : "账号私有"
    user ||--o{ config : "账号级配置（系统级行 user_id=0 无外键）"
    user ||--o{ experience : "账号私有"
    user ||--o{ practice_record : "账号私有"
    user ||--o{ wrong_question : "账号私有"
    user ||--o{ agent_conversation : "账号私有"
    user ||--o{ reminder : "账号私有"
    application ||--o{ jd_analysis_report : "1 条投递可多次分析"
    application ||--o{ interview_session : "选投递记录发起面试"
    interview_session ||--o{ interview_qa : "1 会话 N 题"
    experience ||--o{ experience_item : "1 面经 N 条 Q&A"
    question ||--o{ practice_record : "1 题 N 次陪练"
    question ||--o{ wrong_question : "1 题在错题本至多 1 条（按账号）"
    agent_conversation ||--o{ agent_message : "1 会话 N 消息"
    reminder }o--|| application : "跟进/面试提醒关联投递"
    question : "公共题库，无 user_id"
    campus_event : "公共数据，无 user_id"
```

文字版关系：

- **`user`（账号）是归属根**：账号私有数据均带 `user_id` 外键，删除账号即级联清理其全部私有数据；
- `application`（投递）是业务中心实体：JD 分析、模拟面试、跟进提醒均围绕它，且**仅在所属账号内可见**；
- `question`（题库）为**公共资源**，被所有账号的陪练、错题本共用；`wrong_question` 对 `(user_id, question_id)` 建唯一约束——**同一题在不同账号的错题本中各存一条，互不影响**；
- `interview_session` 允许 `application_id` 为空（用户不选投递、手填公司岗位发起面试）；
- `llm_provider_config` 为**账号 × 供应商**配置表（`user_id + provider` 唯一），每账号至多一行 `is_active=1`；
- `config` 为 key-value 配置表，`user_id` 为 **0 表示系统级配置**（不建外键，见 §3.14）；
- `user_profile` 与账号 1:1（`user_id` 唯一）。

## 3. 表结构详述

### 3.1 application —— 投递记录

对应需求：FR-002~FR-005、FR-013。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK 自增 | 主键 |
| user_id | INTEGER | 非空，FK→user.id | 所属账号（账号私有） |
| company | VARCHAR(100) | 非空 | 公司名称 |
| position | VARCHAR(100) | 非空 | 岗位名称 |
| city | VARCHAR(50) | 可空 | 工作城市 |
| expected_salary | VARCHAR(50) | 可空 | 期望/沟通薪资（自由文本，如 "13k*14"） |
| applied_at | DATETIME | 非空，默认当天 | 投递日期（跟进提醒判定依据） |
| channel | VARCHAR(50) | 可空 | 投递渠道（官网/BOSS/内推等） |
| status | VARCHAR(20) | 非空，默认 `APPLIED` | 进度状态（枚举见第 5 章） |
| close_reason | VARCHAR(20) | 可空 | 结束原因，**仅 `status=CLOSED` 时有值**（枚举见第 5 章）；转其他状态时置空 |

| created_at | DATETIME | 非空 | 创建时间 |
| updated_at | DATETIME | 非空 | 更新时间 |

索引：`idx_application_user(user_id)`、`idx_application_status(status)`、`idx_application_applied_at(applied_at)`。

### 3.9 wrong_question —— 错题本

对应需求：FR-010、FR-013。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK 自增 | 主键 |
| user_id | INTEGER | 非空，FK→user.id | 所属账号（账号私有） |
| question_id | INTEGER | 非空，FK→question.id | 题目（**同账号内一题仅一条**，见下方唯一约束） |
| source_type | VARCHAR(20) | 非空 | 入本来源（枚举见第 5 章） |
| review_stage | INTEGER | 非空，默认 1 | 复习档位 1~4（间隔 1/3/7/15 天） |
| next_review_at | DATETIME | 非空 | 下次复习时间（到期判定依据） |
| wrong_count | INTEGER | 非空，默认 0 | 累计答错次数 |
| last_review_at | DATETIME | 可空 | 最近一次复习时间 |
| mastered_at | DATETIME | 可空 | 掌握时间（走完 4 档后标记，非空=已掌握） |
| created_at | DATETIME | 非空 | 入本时间 |

约束：`UNIQUE(user_id, question_id)` 保证**同一账号内**一题仅一条错题条目（多账号改造前为 `UNIQUE(question_id)`）。索引：`idx_wq_user(user_id)`、`idx_wq_review(next_review_at)`、`idx_wq_stage(review_stage)`。

**复习档位推进规则（与 SRS 4.1 一致）**：答对 `review_stage +1`（4 档满 → 置 mastered_at）；答错 `review_stage 重置为 1`、`wrong_count +1`；每次复习后 `next_review_at = 现在 + 新档位间隔`。

**入本来源补充**：`source_type=INTERVIEW`（面试点评确认入本）时，若知识点不在题库，由服务层先自动创建 question 记录（`source=AI_GENERATED`）再创建错题条目——保证 question_id 外键始终有效。陪练答错入本时若该题已存在错题条目（UNIQUE 约束），更新档位与 wrong_count 而非重复插入。

### 3.14 config —— 系统配置

对应需求：FR-015。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| user_id | INTEGER | 非空，联合主键之一 | 所属账号；**`0` 为保留值，表示系统级配置**（**不建外键**，0 非合法 user 行） |

| value | TEXT | 可空 | 配置值（开关、URL、Key 加密值） |

| 级别 | 键 | 说明 |
|---|---|---|
| 账号级 | `tts_enabled` / `voice_enabled` | TTS 播报、语音作答开关（默认 false） |
| 账号级 | `default_question_count` | 模拟面试默认题量（默认 8） |
| 账号级 | `asr_provider` | ASR 供应商：`funasr`（默认，本地模型）/ `xunfei`（云端备用） |
| 账号级 | `tts_voice` | TTS 音色 ID（edge-tts 音色名，默认 `zh-CN-XiaoxiaoNeural` 晓晓） |
| 账号级 | `asr_app_id` / `asr_api_key` | **仅 `asr_provider=xunfei` 时需要**；Key 以 **Fernet 加密**存 value（P2） |
| 账号级 | `guide_done` | 新手指引是否已读（`true`/`false`，默认 false）；注册后走完或跳过引导置 `true`，个人中心重看不回写（P2） |

### 3.17 llm_provider_config —— AI 供应商配置

对应需求：FR-018。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK 自增 | 主键 |
| user_id | INTEGER | 非空，FK→user.id | 所属账号（**配置按账号隔离**） |
| provider | VARCHAR(30) | 非空 | 供应商标识（注册表 12 项之一，见第 5 章） |
| base_url | VARCHAR(200) | 可空 | API 端点；**空 = 用注册表默认值**（覆盖场景：供应商端点变更、自建代理） |

| model | VARCHAR(100) | 可空 | 该供应商下所选模型（**每家各记一份**，空 = 用注册表默认模型） |

| updated_at | DATETIME | 非空 | 更新时间 |

**激活语义**：保存配置时若该账号尚无激活行，本次保存的供应商自动置 `is_active=1`；切换供应商 = 在同一事务内把旧激活行置 0、目标行置 1（保证至多一行激活）。运行时 Key 读取链见系统设计 5.4。

**模型缓存为何挂在本表**：缓存内容（某 base_url 下有哪些模型）是供应商公开信息、与账号无关，但同一账号同一供应商天然只有一行，挂在行上无需额外表；代价是多账号各自拉一次（12 家供应商、单次 GET /models，可忽略）。

## 6. 容量与性能说明

- 预估总数据量 < 10 万行（见 SRS 4.2），SQLite 单文件即可，无需分库分表；
- 面经/报告等大 TEXT 字段总量 < 50MB，无性能压力；
- 前端列表全部服务端分页（page/page_size，默认 10 条），LIKE 检索限定在面经条目表且结果分页。
- **多账号影响**：数据量随账号数线性增长，但本机单机场景账号数在个位数量级，总量仍在上述量级内；账号级查询一律带 `user_id` 等值条件，各表已建 `idx_*_user` 索引，隔离不带来额外扫表成本。
- **头像文件不入库**：仅存相对路径于 `user.avatar`，实际文件在 `backend/uploads/avatars/`（每张压缩至 256×256，约 20~50KB，量级可忽略）；该目录**已入 `.gitignore`**（`backend/uploads/`）。
- **语音模型不入库**：FunASR 流式模型由 ModelScope 下载到本机缓存目录（约 200~300MB，INT8 量化后），**不在仓库、不在数据库**；TTS 合成结果按 `sha1(text+voice)` 缓存在 `backend/cache/tts/`（单条数秒音频约 10~50KB），该目录**已入 `.gitignore`**（`backend/cache/`），不占用数据库体积。

## 7. 多账号改造升级 SQL（v1.2 → v1.3）

**本项目实际执行路径**：开发库 `backend/app.db` 业务数据为空（10 张业务表 0 行，见 2026-09-25 核对），**直接删除重建**即可——启动时 `init_db` 自动建表、导入题库种子与系统级配置，**无需执行以下脚本**。以下供"库中已有数据"的场景参考（如演示前已录入投递记录）。

### 7.3 重建四张表（约束变更）

| 表 | 旧约束 | 新约束 |
|---|---|---|
| wrong_question | `UNIQUE(question_id)` | `UNIQUE(user_id, question_id)`，新增 `user_id` 列 |
| reminder | `UNIQUE(reminder_type, ref_id, remind_date)` | `UNIQUE(user_id, reminder_type, ref_id, remind_date)`，新增 `user_id` 列 |
| user_profile | 无（靠"仅 id=1 一行"的约定） | `UNIQUE(user_id)`，新增 `user_id` 列 |
| config | `PRIMARY KEY(key)` | `PRIMARY KEY(user_id, key)`，新增 `user_id` 列（系统级行 `user_id=0`） |

四步法：**建新表 → 搬数据 → 删旧表 → 改名**，`PRAGMA foreign_keys=OFF` 须放在事务之外（否则 DROP 会触发级联）。以 `config` 为例：

```sql
PRAGMA foreign_keys = OFF;
BEGIN;
CREATE TABLE config_new (
  user_id    INTEGER     NOT NULL,
  key        VARCHAR(50) NOT NULL,
  value      TEXT,
  updated_at DATETIME    NOT NULL,
  PRIMARY KEY (user_id, key)
);
-- 抓取相关配置为系统级（user_id=0），其余归首个账号
INSERT INTO config_new SELECT 0, key, value, updated_at FROM config
  WHERE key IN ('crawl_enabled','crawl_url');
INSERT INTO config_new SELECT 1, key, value, updated_at FROM config
  WHERE key NOT IN ('crawl_enabled','crawl_url','llm_provider','llm_model','llm_base_url','llm_api_key','llm_models_cache');
DROP TABLE config;
ALTER TABLE config_new RENAME TO config;
COMMIT;
PRAGMA foreign_keys = ON;
```

其余三张同法，仅替换表名与列清单（新表结构照 §3.9 / §3.12 / §3.15 抄写，`user_id` 在搬数据时统一填 `1`）。

### 7.5 AI 配置搬迁（config → llm_provider_config）

老库 `config` 里的 `llm_provider` / `llm_base_url` / `llm_api_key` / `llm_model` 四键转为首个账号的一行配置（有 Key 才建行）：

```sql
INSERT INTO llm_provider_config (user_id, provider, base_url, api_key, model, is_active, created_at, updated_at)
SELECT 1,
       COALESCE((SELECT value FROM config WHERE user_id=1 AND key='llm_provider'), 'deepseek'),
       NULLIF((SELECT value FROM config WHERE user_id=1 AND key='llm_base_url'), ''),
       (SELECT value FROM config WHERE user_id=1 AND key='llm_api_key'),
       (SELECT value FROM config WHERE user_id=1 AND key='llm_model'),
       1, datetime('now'), datetime('now')
WHERE EXISTS (SELECT 1 FROM config WHERE user_id=1 AND key='llm_api_key');
```

**注意**：老库 `api_key` 为明文，新表要求 Fernet 密文——搬迁后须在 AI 配置页重填，或由一次性脚本用 `APP_SECRET_KEY` 加密后再写入；`llm_models_cache` 直接丢弃（按 24h 过期重新拉取即可）。

### 7.6 语音配置键（v1.3 → v1.4，无需 SQL）

语音方案变更**不改表结构**，只在 `config` 表新增两个账号级键：`asr_provider`（默认 `funasr`）、`tts_voice`（默认 `zh-CN-XiaoxiaoNeural`）。老库不必执行任何 SQL——**应用层读取时对缺失键按默认值兜底**，用户首次进设置页保存即落库；注册流程会为新账号预置这两个键（见 §4）。

> 已废弃的口径：原「讯飞语音听写」方案下 `asr_app_id` / `asr_api_key` 是**必填**，现降级为**仅 `asr_provider=xunfei` 时才填**；默认 FunASR 本地模型无凭据。老库中若已存过讯飞 Key，保留不动（切换供应商时仍可用）。

### 7.7 新手指引标记键（v1.4 → v1.5，无需 SQL）

新手指引**不改表结构**，只在 `config` 表新增一个账号级键 `guide_done`（默认 `false`）。老库无需执行 SQL——应用层读取时对缺失键按默认值 `false` 兜底，即老账号会被视作"未读"、下次进首页弹一次引导（可直接跳过，影响可接受）。注册流程为新账号预置该键（见 §4），写入时机为**走完引导或点「跳过」**（`PUT /settings {guide_done: true}`）；个人中心「重看新手指引」**不回写**该键。
