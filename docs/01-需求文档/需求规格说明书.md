## 1. 引言

### 1.1 编写目的

本文档定义"个人求职助手"系统的完整需求，作为设计、开发、测试与验收的**唯一依据**。文档面向三类读者：

- **课程老师**：了解项目定位、功能范围与验收标准；
- **开发成员**：按编号需求逐条实现，不实现本文档未约定的功能；
- **项目使用者**：了解系统功能与操作流程。

### 1.2 项目背景

大四求职季存在典型痛点：投递记录散落在表格与聊天记录中、JD 看不懂匹配度、笔试八股复习无反馈、模拟面试无客观点评、面经看完即忘。本项目面向大四学生，构建覆盖"**投递管理 → JD 匹配分析 → 笔试备战 → AI 模拟面试 → 面经复盘**"全流程的个人求职助手。

产品形态为**工作台**（结构化页面 + 数据看板），而非"聊天框套壳大模型"：AI 能力嵌入每个具体操作流（录入投递、分析 JD、点评答题），同时提供全局 Agent 悬浮球作为快捷入口。

### 1.3 术语与缩略语

| 术语 | 说明 |
|---|---|
| JD | Job Description，岗位描述 |
| OpenAI 兼容协议 | 各家 LLM 服务商通用的 HTTP API 约定（base_url + api_key + model），一套 SDK 可切换多家供应商 |
| LLM | 大语言模型，本项目通过 OpenAI 兼容协议接入所配置的供应商 |
| SSE | Server-Sent Events，服务端推送流式输出协议 |
| STT | Speech To Text，语音转写 |
| TTS | Text To Speech，语音合成播报 |
| Agent | 具备"意图识别 → 工具调用 → 结果回显"能力的智能体，本项目手写实现 |
| 画像 | 用户简历、目标岗位、技能栈等个人背景的结构化摘要 |
| 八股 | 技术面试中高频出现的固定知识点问答（Java/MySQL/网络/操作系统） |

## 2. 项目概述

### 2.1 产品定位

- **单用户本地工具**：无注册登录，数据存本机 SQLite，画像仅一份；
- **AI 原生**：LLM 参与录入、分析、点评、陪练、对话各环节，但所有 LLM 调用均有失败兜底；
- **低延迟优先**：全部 AI 输出走 SSE 流式，首字延迟是最高优先级非功能指标；
- **面向真实求职场景**：功能设计贴合真实求职流程，支持全流程演示与日常使用。

### 2.2 目标用户与典型场景

| 场景 | 用户动作 | 系统行为 |
|---|---|---|
| 早上打开系统 | 进入首页 | 展示今日概览：明日面试置顶、投递统计、3 天无进展提醒、错题到期提醒、就业网宣讲会 |
| 投完一家公司 | 在投递管理点"新增"填表，或对悬浮球说一句话 | 投递入库，看板刷新，3 天后无进展自动提醒 |
| 收到笔试通知 | 看中某条 JD 想判断匹配度 | 粘贴 JD → 流式输出匹配报告（评分+差距+准备建议） |
| 面试前夜 | 选一条投递记录发起模拟面试 | AI 携带公司/岗位上下文逐题发问，语音作答，每题点评打分，会话留存 |
| 看完一篇面经 | 粘贴面经原文 | AI 提取结构化 Q&A 存入面经库，可关键词检索 |
| 等车刷题 | 八股陪练选方向 | 题目卡片 → 作答 → 点评卡片（评分+参考答案），答错自动入错题本 |
| 复习错题 | 错题本"AI 抽问" | 卡片式问答，答对推进复习档位，连续答对标记掌握 |

### 2.3 总体功能结构

```
个人求职助手
├── 今日概览（首页）
│   ├── 待面试提醒（明日/近期面试置顶）
│   ├── 投递进度统计（各状态数量）
│   ├── 跟进提醒（投递 3 天无进展）
│   ├── 错题复习提醒（到期未复习）
│   └── 就业网宣讲会/招聘会
├── 求职工作台
│   ├── 投递管理（增删改查/看板/三种录入方式）
│   ├── JD 匹配分析（粘贴 JD → 流式报告）
│   ├── AI 模拟面试（选投递记录 → 问答 → 点评打分 → 留存）
│   └── 面经整理（粘贴原文 → 结构化存储 → 检索）
├── 笔试备战
│   ├── 八股陪练（选方向 → 答题 → 点评 → 错题联动）
│   └── 错题本（列表 + AI 抽问）
├── 全局 Agent（右下角悬浮球，任意页面唤起）
│   ├── 意图路由（求职/笔试/面经/闲聊）
│   ├── 工具调用（真实执行动作，如新增投递）
│   └── 画像记忆（个性化回答）
└── 系统支撑
    ├── 定时引擎（每日检查提醒/抓取就业网）
    ├── 语音交互（模拟面试语音作答 + TTS 播报，P2）
    └── 系统设置（API 配置/开关/画像编辑）
```

### 2.4 运行环境与约束

| 项 | 约束 |
|---|---|
| 后端 | Python 3.11+，FastAPI，SQLAlchemy 2.x，SQLite（WAL 模式） |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router，Node `^20.19.0 \|\| >=22.12.0`（随 Vite 8） |
| LLM | 多供应商+模型两级可配置（DeepSeek 默认；智谱/Kimi/硅基流动/自定义 OpenAI 兼容接口），模型列表动态拉取保持最新，Key 存 .env，不入库不入前端 |
| 语音 | 讯飞语音听写（P2），Key 存 .env |
| 部署 | 本机运行即可（演示环境）；代码结构保持前后端分离，便于后续云部署 |
| 网络 | 需外网访问 DeepSeek/讯飞；断网时所有 AI 功能降级为可重试的错误提示，主流程数据功能不受影响 |

## 3. 功能需求

> 编号规则：FR-XXX。优先级定义：**P0** = 核心链路，验收必演示；**P1** = 重要功能，第一里程碑内尽量完成；**P2** = 增强功能，第二里程碑实现。

### 3.1 今日概览（FR-001，P0）

**描述**：系统首页，聚合当天求职相关的全部信息，做到"打开就知道今天该干什么"。

**内容区块**：

1. **待面试提醒**：明日有面试/笔试的记录置顶展示（含公司、岗位、时间）；7 日内即将到来的按日期排列。无待办时展示空状态文案。
2. **投递进度统计**：各状态（已投递/待笔试/面试中/已获 offer/已结束）数量统计卡，点击跳转投递管理对应筛选。
3. **跟进提醒**：状态为"已投递"且距投递日期超过 3 天的记录列表，提示"该跟进一下了"。
4. **错题复习提醒**：到期未复习的错题数量与快捷入口。
5. **就业网宣讲会**：定时抓取的近期宣讲会/招聘会列表（时间、地点、企业）。
6. **快捷入口卡片**：新增投递、JD 分析、模拟面试、八股陪练、错题抽问。

**异常场景**：就业网抓取失败 → 该区块显示"暂无数据"与最后抓取时间，不影响其余区块。

### 3.2 投递管理（FR-002~FR-005，P0）

#### FR-002 投递记录维护（P0）

- **字段**：公司、岗位、城市、期望薪资（可选）、投递日期、投递渠道（可选）、进度状态、备注。
- **操作**：新增 / 编辑 / 删除（删除需二次确认）/ 详情查看 / 状态流转。
- **看板展示**：按进度状态分列看板（Kanban），支持状态列间拖拽流转，每条卡片显示公司、岗位、投递天数。

#### FR-003 投递录入三方式（P0）

| 方式 | 说明 |
|---|---|
| 表单录入 | 看板"新增"打开表单，手动填写 |
| Agent 一句话录入 | 对悬浮球说"记一笔：昨天投了南京浩鲸的 Java 开发岗"，Agent 提取字段生成**确认卡片**，用户确认后入库（见 FR-011） |
| 批量导入 | 上传 Excel/CSV 清单（模板提供表头），系统解析后预览 → 确认导入；行级校验，非法行标红提示 |

#### FR-004 投递状态流转（P0）

状态机（详见 4.1 数据字典）：`已投递 → 待笔试 → 面试中 → 已获 offer`；任意非终态可流转至 `已结束`。流转记录时间与备注，供概览与统计使用。

#### FR-005 投递筛选与统计（P1）

按状态/城市/公司关键字筛选；按时间范围查看投递趋势（数量折线）。P1 实现。

### 3.3 JD 匹配分析（FR-006，P0）

**描述**：用户粘贴 JD 文本，系统对比用户画像，流式输出匹配度报告。

**处理流程**：

1. 用户粘贴 JD 全文（或从投递记录一键带入公司/岗位信息）；
2. 系统组装 prompt：画像（简历、技能栈、目标岗位）+ JD 原文；
3. LLM **流式**输出报告（SSE）；
4. 报告落库，关联对应投递记录（若指定）。

**报告结构（固定五段）**：

1. 综合匹配度评分（百分制）；
2. 分项评分：技能匹配 / 经验匹配 / 学历与硬性门槛；
3. 优势清单（画像中与 JD 契合的点）；
4. 差距清单（JD 要求但画像缺失/不足的点，逐条给出补齐建议）；
5. 投递建议与准备建议（简历怎么改、面试重点准备什么）。

**异常场景**：LLM 失败 → 前端提示失败并保留输入内容，可一键重试；报告格式异常 → 按固定结构降级为纯文本流式展示。

### 3.4 AI 模拟面试（FR-007，P0）

**描述**：选择一条投递记录（携带公司/岗位上下文），AI 扮演面试官进行对话式问答，每题点评打分，会话留存。

**处理流程**：

1. 新建会话：选投递记录（必选）或手动填公司/岗位；可选面试方向（Java 后端/前端/通用/数据库等）；
2. AI 开场提问（结合该公司岗位的常见面试题，流式输出）；
3. 用户作答：**文字**输入，或**语音**作答（P2，见 FR-014）；
4. AI 逐题点评：0~10 分 + 亮点 + 不足 + 参考答案要点（流式输出），点评后继续下一题；
5. 用户可随时结束会话 → AI 生成**总结报告**（总评 + 每题意得分 + 改进清单）；
6. 会话与逐题记录留存，可回看。

**规则**：

- 题量默认 8 题，用户可在开始前调整（3~15 题）；
- 每题作答后可跳过（不计分）；
- 同一会话内 AI 保持上下文连贯（追问、根据前文深入）；
- 面试点评的"不足"若涉及具体八股知识点，提示用户该知识点已加入错题本候选（用户确认后入错题本，见 FR-010）。

**异常场景**：LLM 中途失败 → 已完成的问答保留，提示重试继续；会话记录丢失（前端刷新）→ 会话已落库，可恢复。

### 3.5 面经整理（FR-008，P1）

**描述**：粘贴面经原文，AI 结构化存储，支持检索。

**处理流程**：

1. 用户粘贴面经原文 + 可选填公司/岗位/来源；
2. LLM 提取结构化条目（问题 + 答案要点），流式回显供确认；
3. 确认后落库：面经主记录（原文全文）+ 结构化 Q&A 条目列表；
4. 检索：按公司/岗位/关键词（问题内容 LIKE 匹配）搜索条目。

**异常场景**：LLM 提取失败 → 提供"仅保存原文"选项，后续可手动补结构化；原文过长 → 前端限制单次粘贴 10000 字符（超出提示分段）。

### 3.6 八股陪练（FR-009，P0）

**描述**：分方向随机抽题，用户作答，AI 点评，答错自动入错题本。

**处理流程**：

1. 选方向：Java / MySQL / 计算机网络 / 操作系统（多选或全选）；
2. 抽题卡片：题目 + 可选"AI 再出一题"；
3. 用户作答（文本框）；
4. AI 点评卡片：0~10 分 + 参考答案 + 用户答案差距点（流式输出）；
5. 评分 < 6 分（或用户自评"没答好"）→ **自动入错题本**，卡片提示"已加入错题本"。

**题库来源**：内置种子题库（每方向 ≥ 30 题，随仓库发布）；支持"AI 生成题目"（由 Agent 出题后可选入库）。

**异常场景**：LLM 点评失败 → 题目保留，可重试点评；用户可跳过本题。

### 3.7 错题本（FR-010，P0）

**描述**：错题列表 + 复习提醒 + AI 抽问。

**复习规则（定时引擎判定依据，见 FR-013）**：

| 规则 | 说明 |
|---|---|
| 复习档位 | 间隔 1 天 → 3 天 → 7 天 → 15 天，共 4 档 |
| 答对 | 进入下一档，next_review_at = 当前时间 + 下一档间隔 |
| 答错 | 回到第 1 档（1 天后复习） |
| 掌握 | 连续答对 4 次（走完 4 档）→ 标记"已掌握"，移出待复习池 |
| 到期 | next_review_at ≤ 当前时间 → 计入概览"错题复习提醒" |

**AI 抽问**：卡片式问答（展示题目 → 用户作答 → 判定对错并给解析 → 更新档位）。判定对错由 LLM 完成（答案非客观题时），客观题（选择/判断）由标准答案直接判定。

**列表**：展示待复习错题（含到期状态、当前档位）、已掌握错题；支持删除。

### 3.8 全局 Agent（FR-011，P0）

**描述**：右下角悬浮球，任意页面唤起对话浮窗；自然语言驱动，可执行真实动作。

**能力**：

1. **意图路由**：将用户输入路由到四类意图——求职操作 / 笔试学习 / 面经问答 / 闲聊；
2. **工具调用**（可执行真实动作，执行后回显确认卡片）：

| 工具 | 作用 | 回显 |
|---|---|---|
| 新增投递 | 一句话录入（公司/岗位/城市/日期） | 确认卡片（字段预览），用户确认后入库 |
| 查询投递 | 按条件查投递记录 | 列表卡片，点击跳转看板 |
| 更新投递状态 | "XX 公司进面试了" → 状态流转 | 结果卡片 |
| 出题 | "出三道 Java 题" | 题目卡片，可跳转陪练 |
| 错题抽问 | "抽两道错题" | 抽问卡片 |
| 搜面经 | "有没有 XX 公司的面经" | 检索结果卡片 |
| 查提醒 | "我今天有什么事" | 今日概览摘要卡片 |

3. **画像记忆**：回答引用用户画像（如"按你简历里没有微服务经验，这个岗要谨慎"）；对话中可提取新画像信息（见 FR-012）；
4. **快捷指令 chips**：浮窗预设快捷指令——"记一笔投递""出三道 Java 题""今天有什么事""抽两道错题"。

**处理流程**：输入 → 意图路由 → （需要时）LLM 函数调用选择工具 → 前端回显确认/执行 → 流式文字回复。

**异常场景**：LLM 失败 → 提示重试；工具执行失败（如参数缺失）→ 追问补全参数，不静默丢弃。

### 3.9 用户画像（FR-012，P0 基础 / P1 增强）

**描述**：系统对用户求职背景的结构化记忆，供 JD 分析、模拟面试、Agent 回答引用。

**画像字段**：姓名、学校、专业、学历、GPA、英语水平、简历全文、目标岗位、目标城市、技能栈（标签）、弱项（标签）、备注。

**维护方式**：

- **手动编辑**（P0）：设置页表单维护；
- **Agent 自动提取**（P1）：Agent 对话中用户透露的新信息（如"我最近在学 Redis"），LLM 提取后生成"画像更新建议卡片"，用户确认后更新。

### 3.10 定时引擎与提醒（FR-013，P0）

**描述**：后台每日自动执行检查，生成提醒。**判定全用纯规则（日期/状态比较），不调 LLM**；仅生成提醒文案时可调一次 LLM（失败则用模板文案）。

**每日任务**：

| 任务 | 判定规则 | 产出 |
|---|---|---|
| 待面试置顶 | 明日/7 日内有笔试面试（投递状态=待笔试/面试中，且记录的时间字段在未来 7 天内） | 概览置顶数据 |
| 投递跟进 | 状态=已投递 且 今天 − 投递日期 > 3 天 | 跟进列表 |
| 错题到期 | next_review_at ≤ 今天 | 提醒数量 |
| 就业网抓取 | 每日一次，抓取学校就业网公开宣讲会/招聘会信息 | campus_event 表 |

**技术约束**：APScheduler 后台线程执行，不阻塞任何 HTTP 请求；抓取失败静默降级（保留上次数据）。

### 3.11 语音交互（FR-014，P2）

**描述**：模拟面试内的语音作答与 AI 回复播报。文字版主线（P0）跑通后实现。

**语音输入**：

1. 麦克风按钮按下开始录音（按住说话，或点击开始/停止）；
2. 前端 MediaRecorder 录制 3~5 秒短句音频（webm/ogg）；
3. 上传后端 → 讯飞语音听写 API 转写；
4. 转写文字**回填输入框**（不直接提交），用户确认/编辑后提交；
5. 转写失败 → 可重试；始终可用键盘补正，转写不准不阻塞流程。

**语音播报**：AI 回复通过浏览器 speechSynthesis 朗读（设置页开关，**默认关**）。

**性能目标**：单句转写 < 1.5s（短句模式）。

### 3.12 系统设置（FR-015，P0）

| 设置项 | 说明 | 默认值 |
|---|---|---|
| AI 供应商 | 供应商选择（DeepSeek/智谱/Kimi/硅基流动/自定义）+ 对应 API Key + 流式开关 | DeepSeek |
| AI 模型 | 所选供应商下的模型选择（下拉列表；支持"刷新模型列表"动态拉取该供应商最新可用模型） | 供应商默认模型 |
| 连通性测试 | 填写供应商与 Key 后一键测试连通性，返回测试结果 | - |
| 语音配置 | 讯飞 AppID / API Key / 语音输入开关 | 关 |
| TTS 开关 | AI 回复朗读 | 关 |
| 就业网抓取 | 抓取开关 + 目标 URL | 关（演示环境手动触发） |
| 画像编辑 | 见 FR-012 | - |
| 模拟面试默认题量 | 新建会话默认值 | 8 |

**供应商切换规则**：

1. 用户在设置页选择供应商并填写对应 Key，系统保存后**自动生效**（后续 AI 调用无需修改代码、无需重启）；
2. 所有供应商基于 OpenAI 兼容协议接入（见 6.1），切换供应商改变 base_url/api_key、选择模型改变 model——两级配置；模型列表经 GET /models 动态拉取，保证可选模型始终最新；
3. **免费方案**：未开通付费服务时，可选择提供免费模型的供应商（智谱 GLM-4-Flash、硅基流动免费模型等），免费模型存在限速，请求失败走统一 LLM 兜底（重试 + 提示）；
4. 连通性测试：保存前可一键测试，测试失败给出错误原因（Key 无效/网络不通/模型不存在）。

**异常场景**：API Key 无效 → LLM 调用失败时提示"检查设置页供应商与 Key 配置"，引导用户修复；切换供应商后旧 Key 保留不清除，切回即用。

## 4. 数据需求

### 4.1 核心数据字典（枚举口径，全系统统一）

**投递状态（application.status）**：

| 值 | 名称 | 说明 |
|---|---|---|
| APPLIED | 已投递 | 简历已投出，等待反馈（默认） |
| WRITTEN | 待笔试 | 已收到笔试通知 / 笔试流程中 |
| INTERVIEW | 面试中 | 进入面试流程（含多轮面试） |
| OFFER | 已获 offer | 收到录用意向/offer |
| CLOSED | 已结束 | 未通过 / 主动放弃（终态） |

**错题复习状态（wrong_question）**：档位 1/2/3/4（间隔 1/3/7/15 天）、MASTERED（已掌握，移出待复习池）。

**面试方向（interview_session.direction）**：JAVA（Java 后端）/ MYSQL（数据库）/ NETWORK（计算机网络）/ OS（操作系统）/ GENERAL（通用综合）。

**陪练方向（question.direction）**：同上枚举。

**面经条目来源（experience_item）**：LLM_EXTRACT（AI 提取）/ MANUAL（手动补充）。

**模拟面试会话状态（interview_session.status）**：ACTIVE（进行中）/ FINISHED（已结束并生成总结）。

### 4.2 数据规模估计

| 数据 | 量级 | 说明 |
|---|---|---|
| 投递记录 | 数百条 | 秋招季个人使用 |
| 八股题库 | 内置 120+ 条，可增长 | 种子题库随仓库发布 |
| 错题 | 数百条 | 滚动更新，已掌握可删 |
| 面经条目 | 数百至千条 | 全文 + 结构化 |
| Agent 对话 | 数千条消息 | 单机 SQLite 无压力 |

SQLite 完全满足；无需缓存层，直接 SQL 查询（全表扫描在此量级下无性能问题）。

## 5. 非功能需求

### 5.1 性能（NFR-001~004，低延迟为最高优先级）

| 编号 | 指标 | 量化目标 | 测量方式 |
|---|---|---|---|
| NFR-001 | AI 回复首字延迟 | < 2s，之后逐 token 流式（SSE） | 人工计时/日志埋点 |
| NFR-002 | 语音转写延迟 | < 1.5s/句（短句 3~5s 音频） | 人工计时 |
| NFR-003 | 普通 API 响应 | < 200ms（不含 LLM 调用） | 接口压测/计时 |
| NFR-004 | 本地页面操作响应 | < 300ms | 浏览器 DevTools |

**低延迟技术措施（设计与实现必须遵守）**：

1. 所有 LLM 输出走 SSE 流式，**禁止等完整回复再渲染**；
2. 语音用短句模式，不上长音频离线转写；
3. Agent 执行动作采用**乐观更新**：一句话录入投递，前端先出确认卡片，后端确认后刷新列表；
4. 前端 SPA 无整页刷新，流式文本打字机渲染；
5. 定时任务后台线程执行，不阻塞任何请求；
6. 画像/系统 prompt 精简（控制在 1500 token 内），减少输入 token 拖慢首字；
7. SSE 连接建立后服务端立即推送开始事件（"正在分析…"状态文案），界面 300ms 内出反馈，覆盖 LLM 首字前的等待感知。

### 5.2 可用性（NFR-005~007）

| 编号 | 要求 |
|---|---|
| NFR-005 | LLM 异常兜底：调用失败 → 前端明确提示 + 一键重试；任何 LLM 失败不得导致页面白屏或数据丢失 |
| NFR-006 | 降级可用：断网/无 Key 时，投递管理、错题列表、面经检索等纯数据功能完全可用 |
| NFR-007 | 定时任务失败不影响主流程；就业网抓取失败静默降级（保留上次数据 + 显示抓取时间） |

### 5.3 安全（NFR-008~010）

| 编号 | 要求 |
|---|---|
| NFR-008 | 所有 API Key / 密钥存 .env（已 gitignore），任何情况下不出现在代码、前端、文档、日志中 |
| NFR-009 | 全部数据库访问经 SQLAlchemy 参数化查询，禁止字符串拼接 SQL（防注入） |
| NFR-010 | 前端渲染 LLM 输出与用户输入一律转义/使用安全渲染，防 XSS；后端接口做输入长度与类型校验 |

### 5.4 兼容性（NFR-011）

- 浏览器：Chrome / Edge 最新两个大版本（校园机房环境可用）；
- 分辨率：≥ 1280×720 完整显示；
- 系统：Windows 10/11（开发与演示环境）。

### 5.5 可维护性（NFR-012）

- 文档齐全且与代码一致：需求书 → 设计文档 → 数据库设计 → 接口文档 → 测试计划 → 开发计划；
- 测试：pytest 覆盖核心服务与 API，**LLM 调用全部 mock**（不产生 API 调用费用，测试可离线跑）；
- 代码结构分层清晰（API 层 / 服务层 / 数据层），详见系统设计文档。

## 6. 外部接口需求

### 6.1 LLM 供应商与模型

- 用途：JD 分析、面试官、八股点评、面经结构化、Agent 对话与工具选择；
- 接入协议：全部供应商基于 **OpenAI 兼容协议**（统一 base_url + api_key + model 三要素，SDK 零改动切换）；
- 配置粒度：**供应商 → 模型**两级，先选供应商（决定 base_url 与 Key），再选该供应商下的具体模型；

| 供应商 | base_url | 代表模型（内置表，随版本更新） | 免费可用性 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com` | **deepseek-flash**（V4.1 Flash，默认）/ deepseek-v4-pro（退役路由中） | 注册赠送额度 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | glm-4.7-flash / glm-4-flash | Flash 系列长期免费 |
| Kimi（月之暗面） | `https://api.moonshot.cn/v1` | kimi-k2.6 / kimi-k2.7-code / kimi-k3 | 新用户赠送额度 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | Qwen3-8B 等 | 9B 以下模型永久免费 |
| 自定义 | 用户填写 | 用户填写 | 视供应商而定 |

**模型列表动态更新（保证"最新可用版本"）**：

1. OpenAI 兼容协议提供 `GET /models` 端点，返回该供应商当前全部可用模型；
2. 设置页选择供应商后自动拉取其模型列表（下拉选择），"刷新模型列表"按钮强制重拉；
3. 拉取结果缓存 24 小时；拉取失败回退内置模型表（UI 标注"内置列表"）；
4. 内置模型表随项目版本维护更新，运行时以动态拉取为准。

**模型退役兜底**：供应商退役模型 ID 时通常自动路由到替代模型（如 deepseek-v4-pro 退役后路由到 deepseek-flash）；调用返回"模型不存在"时，提示用户去设置页重选模型（错误码 10013 含此原因）。

**其他约定**：

- 默认模型：DeepSeek deepseek-flash（V4.1 Flash，内置思考/非思考模式）；深度分析场景可配置带推理能力的模型（配置项，默认仍用 flash 保证延迟）；
- 切换方式：设置页选择供应商与模型并填写对应 Key，系统保存后自动生效（见 FR-015）；
- 免费方案：未开通付费服务时切换至免费模型（智谱 Flash 系列、硅基流动 9B 以下模型等）；免费模型有限速，请求失败走统一 LLM 兜底（重试 + 提示）；
- 全部流式（stream=True），超时与重试策略见系统设计文档。

### 6.2 讯飞语音听写 API（P2）

- 用途：模拟面试语音作答转写；
- 接入方式：讯飞开放平台 WebSocket API，短句听写模式（3~5s 音频）；
- 备选：阿里云智能语音交互（同能力），实现时抽象供应商接口，可配置切换。

### 6.3 学校就业网（抓取）

- 用途：每日抓取宣讲会/招聘会公开信息；
- 目标：南京理工大学就业网公开页面（URL 在设置页可配）；
- 约束：只抓公开列表信息，不做登录、不绕过反爬、频率每日 1 次；失败静默降级。

## 7. 范围边界（明确不做）

| 不做项 | 原因 |
|---|---|
| 校园跑腿 / 二手交易 / 财务记账 | 与求职主线无关 |
| 招聘数据全网爬虫与分析 | 超出个人工具定位、有合规风险；就业网单一站点定时抓取除外 |
| 邮箱自动接入 | 作为"后续规划"方向保留一句，不在本期范围 |
| LangChain / 框架化 Agent | 课程要求体现手写 Agent 能力（意图路由+工具注册+画像记忆） |
| 本地语音模型部署（Whisper 等） | 部署重、演示环境不可控；用云 STT |
| 用户注册登录 / 多用户 | 单用户本地工具 |
| 简历自动生成/投递机器人 | 涉及第三方网站自动化，合规风险 |
| 移动端 App | 课设范围外，前端响应式保证窄屏可用即可 |
