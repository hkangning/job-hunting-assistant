## 1. 引言

### 1.1 编写目的

本文档定义"个人求职助手"系统的完整需求，作为设计、开发、测试与验收的**唯一依据**。文档面向三类读者：

- **课程老师**：了解项目定位、功能范围与验收标准；
- **开发成员**：按编号需求逐条实现，不实现本文档未约定的功能；
- **项目使用者**：了解系统功能与操作流程。

### 1.2 项目背景

大四求职季存在典型痛点：投递记录散落在表格与聊天记录中、**校招信息散落在各校就业网站与平台上**（只盯本校会漏掉外地机会，多校逐个刷又看不过来）、JD 看不懂匹配度、笔试八股复习无反馈、模拟面试无客观点评、面经看完即忘。本项目面向大四学生，构建覆盖"**信息获取 → 投递管理 → JD 匹配分析 → 笔试备战 → AI 模拟面试 → 面经复盘**"全流程的个人求职助手。

产品形态为**工作台**（结构化页面 + 数据看板），而非"聊天框套壳大模型"：AI 能力嵌入每个具体操作流（录入投递、分析 JD、点评答题），同时提供全局 Agent 悬浮球作为快捷入口。

### 1.3 术语与缩略语

| 术语 | 说明 |
|---|---|
| JD | Job Description，岗位描述 |
| 校招情报 | 本项目的多源校招信息聚合模块（FR-021）：把多所高校就业网站发布的宣讲会 / 双选会 / 岗位汇聚到一处，去重、检测变更、按画像排序、命中订阅即提醒 |
| 信息源 | 一条抓取配置（`crawl_source` 表一行）：某所学校使用的某个就业网站系统；**新增一所学校 = 新增一行配置**，不写代码 |
| 投喂 | 用户手动把校招信息交给系统（粘贴 JD 文本或链接，见 FR-021）——与自动抓取互补，抓不到或没有源的信息由投喂兜底 |

| SSE | Server-Sent Events，服务端推送流式输出协议 |
| STT / ASR | Speech To Text，语音转写；本项目 ASR 供应商可切换（FunASR 本地 / 讯飞云端） |
| TTS | Text To Speech，语音合成播报；本项目用 edge-tts 合成、音色可选 |
| FunASR | 阿里开源的语音识别工具包，本项目用其流式模型 `paraformer-zh-streaming` 做**本地**转写（进程内、CPU 可跑、不限时长） |

## 2. 项目概述

### 2.1 产品定位

- **多账号本地工具**：需注册登录后使用，数据存本机 MySQL；**每个账号的求职数据、画像、AI 配置完全隔离**，互不可见、互不影响；
- **信息聚合**：校招信息不局限于本校就业网——聚合多所高校就业网站的宣讲会 / 双选会 / 岗位（国内高校就业网站集中在三家系统厂商，一套解析器可覆盖多校），跨源去重、变更检测（宣讲会改期即提醒）、按画像排序，订阅命中写站内提醒；用户不必逐个网站刷，也不必自己盯改期；
- **AI 原生**：LLM 参与录入、分析、点评、陪练、对话各环节，但所有 LLM 调用均有失败兜底；
- **AI 供应方可选**：支持 12 家供应商（含国外主流与本地 Ollama），**每家 Key 分别保存、一键切换**，用户按网络条件与成本自行选择；
- **低延迟优先**：全部 AI 输出走 SSE 流式，首字延迟是最高优先级非功能指标；
- **面向真实求职场景**：功能设计贴合真实求职流程，支持全流程演示与日常使用；
- **部署形态**：个人电脑本地运行（演示环境），也可整体部署到服务器单实例运行；不做多实例与生产级加固。

### 2.2 目标用户与典型场景

| 场景 | 用户动作 | 系统行为 |
|---|---|---|
| 首次使用 | 打开系统 | 播放入场动画（约 1.8 秒）→ 自动进入登录页 → 切换到注册页创建账号 |
| 首次注册完成 | 注册成功后进入首页 | **自动弹出新手指引**：分步高亮投递管理 → JD 分析 → 模拟面试 → 陪练/错题 → AI 配置，每步可跳过；走完或跳过后不再自动弹出 |
| 日常打开（已登录） | 打开系统 | 入场动画播放完毕后**直接进入今日概览**（无需再次登录） |
| 换人使用 | 点右上角用户名 → 退出登录 → 登录另一账号 | 界面数据、画像、AI 配置全部切换为该账号所有，互不串数据 |
| 配置 AI | 点右上角用户名 → AI 配置 | 逐家填写供应商 Key 与模型（可配多家），保存后一键切换当前使用的供应商 |
| 早上打开系统 | 进入首页 | 展示今日概览：明日面试置顶、投递统计、3 天无进展提醒、错题到期提醒、**校招情报摘要**（近期宣讲会/双选会 + 匹配度最高的岗位 + 订阅命中数） |
| 想看看最近有哪些机会 | 打开侧栏「校招情报」 | 宣讲会 / 双选会 / 岗位分 Tab 展示，可按城市、公司、时间筛选；默认按时间排序，可切「匹配度」排序（命中画像目标城市 / 方向 / 专业的排前面） |
| 看到心动的岗位 | 卡片上点「加入投递」或「分析匹配度」 | 加入投递 = 跳新建表单并预填公司 / 岗位 / 渠道 / 原文链接；分析匹配度 = 跳 JD 分析页并预填岗位描述 |
| 想一直盯着某类机会 | 在校招情报页配置订阅规则（关键词 / 公司 / 城市 / 类型） | 新信息入库或原信息发生变更时逐条比对规则，**命中即写入站内提醒**（概览与提醒列表可见），同一条同日不重复打扰 |
| 某场宣讲会改期了 | ——（系统自动检测） | 卡片打「已变更」角标；命中订阅的账号收到提醒（"你关注的 ×× 宣讲会改期了"） |
| 想知道这周有哪些安排 | 校招情报页切「日历」视图 | 月视图一次展示宣讲会 / 双选会 / 笔试 / 面试四类事件；点日期看当日事件，点事件跳详情 |
| 别处看到的招聘信息 | 在校招情报页粘贴 JD 文本或链接 | AI 抽取字段返回预览，确认后入库（**该记录为本账号私有**，其他账号不可见）；抽取失败可改手动填表 |
| 投完一家公司 | 在投递管理点"新增"填表，或对悬浮球说一句话 | 投递入库，看板刷新，3 天后无进展自动提醒 |
| 收到笔试通知 | 看中某条 JD 想判断匹配度 | 粘贴 JD → 流式输出匹配报告（评分+差距+准备建议） |
| 面试前夜 | 选一条投递记录发起模拟面试，可选题源（该条投递的 JD / 错题本 / 面经等） | AI 按题源上下文逐题发问，追问引用作答原话；语音作答，每题给内容与表达两类点评，会话留存 |
| 自我介绍 / 项目讲解说不顺 | 把这段内容建成一道练习题，反复练同一道题 | 每遍给内容与表达点评；多遍后给出进步对比（填充词、时长、停顿次数） |
| 面完一场想改进 | 从历史会话或错题本取当时答不好的题，建为练习题重练 | 重练结果与历史记录并列，看得出改进了没有 |
| 看完一篇面经 | 粘贴面经原文 | AI 提取结构化 Q&A 存入面经库，可关键词检索 |
| 等车刷题 | 八股陪练选方向 | 题目卡片 → 作答 → 点评卡片（评分+参考答案），答错自动入错题本 |
| 复习错题 | 错题本"AI 抽问" | 卡片式问答，答对推进复习档位，连续答对标记掌握 |

### 2.3 总体功能结构

### 2.4 运行环境与约束

| 项 | 约束 |
|---|---|
| 后端 | Python 3.11+，FastAPI，SQLAlchemy 2.x，**MySQL 8.0**（InnoDB，`utf8mb4`）；认证用 JWT |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router，Node `^20.19.0 \|\| >=22.12.0`（随 Vite 8） |
| LLM | **12 家供应商**可配置（国内：DeepSeek/智谱/Kimi/通义千问/豆包；国外：OpenAI/Gemini/Claude/Grok；聚合：OpenRouter；本地：Ollama；以及自定义 OpenAI 兼容端点），每家独立保存 Key 与所选模型、一键切换；模型列表动态拉取保持最新 |
| 密钥存储 | **AI 供应商 Key 按账号加密存库**（Fernet 对称加密，密钥来自 .env，见 NFR-008）；讯飞语音 Key（选用云端时）按账号存库同规则；接口永不回显明文。FunASR 本地与 edge-tts **无需 Key** |
| 信息采集 | `httpx` + `lxml`——三家高校就业网站系统均为**服务端渲染页面或免登录 JSON 接口**，无需浏览器内核；**不引入 Playwright / Selenium**（避免重依赖与"绕过技术防护"的合规风险） |
| 语音 | **ASR**：FunASR 本地流式模型（默认，进程内运行、不限时长）或讯飞云端；**TTS**：edge-tts（音色鲜活、免费，P2） |
| 部署 | **本机运行 + 可选服务器部署**（演示与个人使用），单实例；数据库 **MySQL 8.0 单库**（本机或服务器同构）；不做多实例、HTTPS 终结、容器化等生产级加固。语音模型**首次使用需联网下载一次**（AutoModel 从 ModelScope 拉取，约数百 MB），之后离线可用 |
| 网络 | 国外供应商需自备网络环境；断网时所有 AI 功能降级为可重试的错误提示，主流程数据功能不受影响；**语音识别走本地模型、播报走 edge-tts（合成结果可缓存），断网不影响演示**；Ollama 本地模型可作为无外网环境下的 LLM 兜底 |

## 3. 功能需求

> 编号规则：FR-XXX。优先级定义：**P0** = 核心链路，验收必演示；**P1** = 重要功能，第一里程碑内尽量完成；**P2** = 增强功能，第二里程碑实现。

### 3.1 今日概览（FR-001，P0）

**描述**：系统首页，聚合当天求职相关的全部信息，做到"打开就知道今天该干什么"。

**内容区块**：

1. **待面试提醒**：明日有面试/笔试的记录置顶展示（含公司、岗位、时间）；7 日内即将到来的按日期排列。无待办时展示空状态文案。
2. **投递进度统计**：各状态（已投递/待笔试/面试中/已获 offer/已结束）数量统计卡，点击跳转投递管理对应筛选。
3. **跟进提醒**：状态为"已投递"且距投递日期超过 3 天的记录列表，提示"该跟进一下了"。
4. **错题复习提醒**：到期未复习的错题数量与快捷入口。
5. **校招情报摘要**：近期宣讲会/双选会列表（时间、地点、企业）+ **匹配度最高的若干条岗位** + 命中订阅的提醒计数（见 FR-021）；发生变更（改期等）的条目打「已变更」角标。
6. **快捷入口卡片**：新增投递、JD 分析、模拟面试、八股陪练、错题抽问。

**异常场景**：信息源抓取失败 → 该区块展示上次抓到的数据与最后抓取时间，并标注"部分来源暂不可用"，不影响其余区块；全部来源均无数据时显示"暂无数据"。

### 3.2 投递管理（FR-002~FR-005，P0）

#### FR-002 投递记录维护（P0）

- **字段**：公司、岗位、城市、期望薪资（可选）、投递日期、投递渠道（可选）、进度状态、备注。
- **操作**：新增 / 编辑 / 删除（删除需二次确认）/ 详情查看 / 状态流转。
- **看板展示**：按进度状态分列看板（Kanban），支持状态列间拖拽流转，每条卡片显示公司、岗位、投递天数。

#### FR-003 投递录入三方式（P0）

| 方式 | 说明 |
|---|---|
| 表单录入 | 看板"新增"打开表单，手动填写 |
| Agent 一句话录入 | 对悬浮球说"记一笔：昨天投了南京浩鲸的 Java 开发岗"，Agent 提取字段生成**确认卡片**，用户确认后入库（见 FR-011） |
| 批量导入 | 上传 Excel/CSV 清单（模板提供表头），系统解析后预览 → 确认导入；行级校验，非法行标红提示 |

#### FR-004 投递状态流转（P0）

状态机（详见 4.1 数据字典）：链上顺序为 `已投递 → 待笔试 → 面试中 → 已获 offer`；**可前进到链上任意更靠后的状态**——跳过环节合法（有些公司不设笔试，`已投递` 可直接进 `面试中`；同理 `已投递 → 已获 offer`、`待笔试 → 已获 offer` 亦合法），亦可终止；除 `已结束` 外任意状态均可流转至 `已结束`（含 `已获 offer`——覆盖拒 offer、offer 被撤回、谈崩等情形）。**不可回退**（如 `面试中 → 待笔试` 被拒）。**流转至 `已结束` 时必须指明结束原因**（`未通过` / `主动放弃` / `无消息`，见 4.1 数据字典）——三类处境对应完全不同的复盘动作（补短板 / 无需复盘 / 查简历与渠道），不作区分的「已结束」没有信息量。流转记录时间、原因与备注，供概览与统计使用。

#### FR-005 投递筛选与统计（P1）

按状态/城市/公司关键字筛选；按时间范围查看投递趋势（数量折线）。P1 实现。

### 3.3 JD 匹配分析（FR-006，P0）

**描述**：用户粘贴 JD 文本，系统对比用户画像，流式输出匹配度报告。

**处理流程**：

1. 用户粘贴 JD 全文（或从投递记录一键带入公司/岗位信息）；
2. 系统组装 prompt：画像（简历、技能栈、目标岗位）+ JD 原文；
3. LLM **流式**输出报告（SSE）；
4. 报告落库，关联对应投递记录（若指定）。

**报告结构（固定五段）**：

1. 综合匹配度评分（百分制）；
2. 分项评分：技能匹配 / 经验匹配 / 学历与硬性门槛；
3. 优势清单（画像中与 JD 契合的点）；
4. 差距清单（JD 要求但画像缺失/不足的点，逐条给出补齐建议）；
5. 投递建议与准备建议（简历怎么改、面试重点准备什么）。

**异常场景**：LLM 失败 → 前端提示失败并保留输入内容，可一键重试；报告格式异常 → 按固定结构降级为纯文本流式展示。

### 3.4 AI 模拟面试（FR-007，P0）

**描述**：选择一条投递记录（携带公司/岗位上下文），AI 扮演面试官进行对话式问答，每题点评打分，会话留存。

**处理流程**：

1. 新建会话：选投递记录（必选）或手动填公司/岗位；可选面试方向（Java 后端/前端/通用/数据库等）；可选题源（见下方规则）；
2. AI 开场提问（按题源上下文出题，流式输出）；
3. 用户作答：**文字**输入，或**语音**作答（P2，见 FR-014）；
4. AI 逐题点评：0~10 分 + 亮点 + 不足 + 参考答案要点（流式输出），点评后继续下一题；**语音作答同时产出表达维度点评**（见 FR-014）；
5. 用户可随时结束会话 → AI 生成**总结报告**（总评 + 每题意得分 + 改进清单；含语音作答时附表达维度汇总）；
6. 会话与逐题记录留存，可回看。

**题源**（默认通用随机）：

| 题源 | 取材 |
|---|---|
| 投递记录 | 该条投递的 JD 原文 |
| 错题本 | 尚未掌握的错题知识点 |
| 面经 | 已结构化的问题条目 |
| 简历 | 画像中的简历全文，由 AI 提取可追问的项目点 |
| 通用随机 | 内置方向题库 |
| 自定义 | 用户手写题面 |

**规则**：

- 题量默认 8 题，用户可在开始前调整（3~15 题）；
- 每题作答后可跳过（不计分）；
- 同一会话内 AI 保持上下文连贯（追问、根据前文深入）；**追问须引用作答原话**（如"你刚提到用 Redis 锁拦住了大部分请求，那锁失效时怎么办"），不复述模板化问题；
- 用户表达"没听清""能重复一下问题吗""我想补充一点"时，按对应意图处理（复述问题 / 允许补充），**不当作新题跳过**；
- 面试点评的"不足"若涉及具体八股知识点，提示用户该知识点已加入错题本候选（用户确认后入错题本，见 FR-010）；语音作答的**停顿点**落在专业名词上时，同样提示入本候选。

**异常场景**：LLM 中途失败 → 已完成的问答保留，提示重试继续；会话记录丢失（前端刷新）→ 会话已落库，可恢复。

### 3.5 面经整理（FR-008，P1）

**描述**：粘贴面经原文，AI 结构化存储，支持检索。

**处理流程**：

1. 用户粘贴面经原文 + 可选填公司/岗位/来源；
2. LLM 提取结构化条目（问题 + 答案要点），流式回显供确认；
3. 确认后落库：面经主记录（原文全文）+ 结构化 Q&A 条目列表；
4. 检索：按公司/岗位/关键词（问题内容 LIKE 匹配）搜索条目。

**异常场景**：LLM 提取失败 → 提供"仅保存原文"选项，后续可手动补结构化；原文过长 → 前端限制单次粘贴 10000 字符（超出提示分段）。

### 3.6 八股陪练（FR-009，P0）

**描述**：按技术栈与领域两级筛选随机抽题，用户作答，AI 点评，答错自动入错题本。

**处理流程**：

1. **选题**——两级筛选：先选**技术栈**（Java 后端 / Python / AI·Agent / 后端通用 / 计算机通用基础），再在其中选**领域**（如 Java 后端下含 Java 语言、JVM、并发、Spring；后端通用下含 MySQL、Redis、消息队列；计算机通用基础下含网络、操作系统、算法、设计模式）；支持多选与全选；
2. **抽题**——按筛选条件随机出题（题目 + 可选"AI 再出一题"）。题型分三类：**主观题**（LLM 判定）、**客观题**（规则判定对错、不调 LLM）、**场景题**（LLM 按四维度评分）；
3. 用户作答（文本框）——场景题按"如果让你设计 / 排查……"的开放叙述作答；
4. **AI 点评卡片**（流式输出，0~10 分 + 与用户答案的差距点）：
   - 主观题 / 客观题——附参考答案对照；
   - **场景题——按四维度分别点评**：**解题框架**（是否先给结构再补细节）、**量化估算**（是否有容量 / 数量级推算）、**取舍权衡**（是否说明方案的代价与替代）、**兜底降级**（是否交代失败路径）；场景题展示**参考框架**而非"标准答案"；
5. 评分 < 6 分（或用户自评"没答好"）→ **自动入错题本**，卡片提示"已加入错题本"。

**题库来源**：内置种子题库（**585 题**，覆盖 5 个技术栈 / 18 个领域，其中**场景题 152 道**——岗位范围不限于 Java 后端，含 Python 与 AI·Agent 方向；随仓库发布，首次启动自动入库，题库文件升级时按 `content` upsert 补齐）；支持"AI 生成题目"（由 Agent 出题后可选入库）。

**异常场景**：LLM 点评失败 → 题目保留，可重试点评；用户可跳过本题。

### 3.7 错题本（FR-010，P0）

**描述**：错题列表 + 复习提醒 + AI 抽问。

**复习规则（定时引擎判定依据，见 FR-013）**：

| 规则 | 说明 |
|---|---|
| 复习档位 | 间隔 1 天 → 3 天 → 7 天 → 15 天，共 4 档 |
| 答对 | 进入下一档，next_review_at = 当前时间 + 下一档间隔 |
| 答错 | 回到第 1 档（1 天后复习） |
| 掌握 | 连续答对 4 次（走完 4 档）→ 标记"已掌握"，移出待复习池 |
| 到期 | next_review_at ≤ 当前时间 → 计入概览"错题复习提醒" |

**AI 抽问**：卡片式问答（展示题目 → 用户作答 → 判定对错并给解析 → 更新档位）。判定对错由 LLM 完成（答案非客观题时），客观题（选择/判断）由标准答案直接判定。

**列表**：展示待复习错题（含到期状态、当前档位）、已掌握错题；支持删除。

**描述**：右下角悬浮球，任意页面唤起对话浮窗；自然语言驱动，可执行真实动作。

**能力**：

1. **意图路由**：将用户输入路由到四类意图——求职操作 / 笔试学习 / 面经问答 / 闲聊；
2. **工具调用**（可执行真实动作，执行后回显确认卡片）：

| 工具 | 作用 | 回显 |
|---|---|---|
| 新增投递 | 一句话录入（公司/岗位/城市/日期） | 确认卡片（字段预览），用户确认后入库 |
| 查询投递 | 按条件查投递记录 | 列表卡片，点击跳转看板 |

### 3.10 定时引擎与提醒（FR-013，P0）

**描述**：后台每日自动执行检查，**按账号**生成提醒。**判定全用纯规则（日期/状态比较），不调 LLM**；仅生成提醒文案时可调一次 LLM（失败则用模板文案）。

**每日任务**：

| 任务 | 判定规则 | 产出 | 执行范围 |
|---|---|---|---|
| 待面试置顶 | 明日/7 日内有笔试面试（投递状态=待笔试/面试中，且记录的时间字段在未来 7 天内） | 概览置顶数据 | **逐账号** |
| 投递跟进 | 状态=已投递 且 今天 − 投递日期 > 3 天 | 跟进列表 | **逐账号** |

| 校招信息采集 | 每日一次，逐源抓取各高校就业网站公开的宣讲会 / 双选会 / 岗位信息（源配置见 FR-021） | `campus_event` / `job_posting` 表 | **全站一次**（公共数据） |

**技术约束**：APScheduler 后台线程执行，不阻塞任何 HTTP 请求；抓取失败静默降级（保留上次数据）。**提醒类任务遍历全部账号分别判定**（各账号只依据自己的投递与错题数据，提醒记录归属该账号）；**校招信息采集为公共数据，全站每日仅执行一次**，结果所有账号共享；**单源隔离**——任一源抓取失败只标记该源状态（见 FR-021），不影响其余源，也不影响提醒等其他每日任务。

### 3.11 语音交互（FR-014，P2）

**描述**：模拟面试与练习模式内的**长时长语音作答**（一场可连续使用，单轮作答 1~5 分钟）与 AI 回复的**自然语音播报**；语音作答在转写之外**同时产出表达力指标**，用于表达维度点评。文字版主线（P0）跑通后实现。

**语音输入（长时长连续交互）**：

1. 点击「开始作答」开启麦克风，用户**连续说话**，一轮完整作答无需反复按键；
2. 前端 MediaRecorder 持续录音 + **静音检测（VAD）自动断句**：检测到静音即切出一句（3~15s），逐句上传后端转写，结果**累积回填输入框**（边说边出字）；**静音阈值按当前语速自适应**（说得快 1.6s / 正常 2.65s / 说得慢 3.6s），避免说话偏慢的用户被过早打断；
3. 后端 ASR 转写：**默认 FunASR 本地流式模型**（进程内运行、不出网、不限时长），可在设置页切换讯飞云端；单句转写目标 < 1.5s；
4. 用户可随时停止录音，转写文字**不直接提交**——确认/编辑后再提交；
5. **提交作答时一并上传分句时间轴**：前端将本次作答每句的起止毫秒与**原始转写文本**随作答提交（格式见接口文档）——VAD 在前端执行，**该数据仅前端可得，缺失则无法产出表达维度**；
6. 单句转写失败可重试；始终可用键盘补正，转写不准不阻塞流程。

**表达力分析（语音作答独有，与内容点评分列）**：

| 指标 | 含义 | 参考区间 |
|---|---|---|
| 语速 | 字数 ÷ 有效语音时长（字/分钟） | 180~240 |
| 填充词密度 | "嗯 / 呃 / 那个 / 就是 / 然后"等占字数的比例 | < 2% |
| 停顿点 | 句间间隔 > 1.5s 的位置及其前文词 | 越少越好 |
| 有效时长占比 | 有效语音时长 ÷ 作答总时长 | > 70% |
| 流畅度趋势 | 作答前 / 中 / 后三段的语速走向 | 平稳或递增 |

- 五项指标由后端**纯算法计算**（不调用 LLM），作答提交后即时可得；**参考区间为经验值，不作为评分依据**，仅用于生成点评时的措辞分档；
- 解读性点评由 LLM 生成，须**引用原话**；
- 作答时长不足 10 秒或纯文字作答时**不产出表达维度**，报告相应位置不展示；
- 指标基于**语音原始转写**计算——用户编辑转写文本只影响内容点评，不重算指标；
- 点评措辞统一使用「停顿」，**不使用「卡壳」「结巴」等定性词**：静音检测无法区分「想不起来」与「换气思考」，定性表述会误伤。

**语音播报（TTS）**：

1. AI 点评/回复经**后端合成音频**返回，前端播放（设置页开关，**默认关**）；
2. **音色鲜活可选**：内置 edge-tts 中文音色（晓晓 / 云希 / 云扬等 20+），设置页选择、按账号保存；
3. 播放可打断（停止按钮 / 切换题目即停）。

**供应商可切换（与 AI 供应商同思路）**：ASR 供应商 `funasr`（本地，默认）/ `xunfei`（云端），TTS 音色账号级保存；**默认组合零注册、零费用、不依赖外网**（答辩断网可用），云端方案作为备选。

**性能目标**：单片段转写 < 1.5s（按 VAD 切出的 3~15s 片段计；FunASR 本地 CPU 实测约 600ms 出字）。

### 3.13 账号体系（FR-016，P0）

**描述**：系统的使用门槛。**所有求职数据归属账号**，未登录不可使用任何业务功能。

#### 3.13.1 注册

| 字段 | 规则 |
|---|---|
| 用户名 | 必填，3~20 位，仅限字母 / 数字 / 下划线，**全站唯一**，注册后不可修改（登录凭据） |
| 密码 | 必填，**≥6 位**（不强制字符类型，页面给出强度提示但不拦截提交） |
| 确认密码 | 必填，与密码一致 |
| 昵称 | 选填，默认取用户名，可在个人中心修改 |
| 邮箱 | 选填，填写时校验格式且全站唯一（为后续高级功能预留） |

**规则**：

1. 注册成功后**自动登录并进入今日概览**（无需再手动登录一次）；
2. 密码以 **bcrypt 哈希**存储，任何情况下不存明文、不可逆推；
3. 用户名重复 → 错误码 80003，前端在用户名输入框标红提示；
4. 本系统为本地工具，注册开放、无需邀请码；**首个注册的账号 `role=ADMIN`**，其余为 `USER`（角色字段本期不启用权限差异，为后续管理功能预留）；
5. 用户表预置 `plan` 字段（`FREE` / `PRO`），本期不启用，为后续高级功能预留。

#### 3.13.2 登录与会话

| 项 | 规则 |
|---|---|
| 登录凭据 | 用户名 + 密码 |
| 失败提示 | 统一提示"用户名或密码错误"（80004），**不区分**用户名不存在与密码错误（防用户名枚举） |
| 免登录选项 | 登录页提供"**30 天免登录**"勾选框。**勾选**：登录态保持 30 天；**不勾选**：登录态保持 1 天 |
| 会话凭据 | JWT Token，前端存储并在后续请求通过 `Authorization: Bearer <token>` 携带 |
| 登录失败锁定 | 同一账号连续失败 **5 次**锁定 **5 分钟**（错误码 80005），锁定期间即使密码正确也拒绝登录；登录成功清零计数 |
| 登出 | 用户菜单提供"退出登录"，前端清除本地 Token 并跳回登录页（JWT 无状态，不做服务端黑名单） |
| 登录态失效 | Token 过期或无效 → 任意接口返回 80001/80002，前端清除本地 Token 并跳转登录页 |
| 登录时间 | 每次登录成功记录 `last_login_at`，个人中心展示 |

#### 3.13.3 启动与登录流程

1. 打开系统 → 播放入场动画（品牌图案 + 文字，约 1.8 秒，**点击任意处可跳过**）；
2. 动画期间**并行校验本地 Token**：
   - Token 有效 → 动画结束后**直接进入今日概览**；
   - 无 Token 或已失效 → 动画结束后进入登录页；
3. 动画在**同一浏览器会话内只播放一次**（切到登录页、登录成功后跳转均不再播放）；
4. 已登录用户刷新页面不重复播放动画。

**描述**：账号自身的管理页。**入口为右上角用户菜单（头像 + 用户名），与侧边导航的求职流程分离**。

**页面内容**：

| 区块 | 内容 |
|---|---|

**供应商切换规则**：

1. 用户为某供应商填写 Key 并保存后，可点击"设为当前使用"，系统**自动生效**（后续 AI 调用无需改代码、无需重启）；
2. 所有供应商基于 **OpenAI 兼容协议**接入（见 6.1），`base_url` + `api_key` + `model` 三要素决定一次调用；
3. **多供应商并存**：不同供应商的 Key 与模型各自独立保存，切换只改变"当前生效"标记，**已保存的配置与 Key 不清除**，切回即用；
4. **模型列表动态拉取**：选择供应商后拉取其可用模型列表（`GET /models`），支持"刷新模型列表"强制重拉；结果缓存 24 小时，拉取失败回退内置模型表（UI 标注"内置列表"）；
5. **删除配置**：可删除某供应商已保存的 Key 与模型配置（仅影响该供应商，其余供应商不受影响）；删除当前生效的供应商时，系统提示 AI 功能将不可用，直至重新配置；
6. **连通性测试**：保存前可一键测试，向该供应商发送最小请求验证连通性（不落库）；失败返回具体原因（Key 无效 / 网络不通 / 模型不存在）；
7. **免费方案**：未开通付费服务时，可选择提供免费额度的供应商（智谱 Flash 系列、通义千问、豆包等均有免费额度）；免费模型存在限速，请求失败走统一 LLM 兜底（重试 + 提示）；
8. **本地兜底**：Ollama 本地模型无需 Key 与外网，可作为断网环境下的可用方案。

**异常场景**：Key 无效或未配置 → LLM 调用失败时提示"检查 AI 配置页供应商与 Key"，引导用户跳转 AI 配置页修复（错误码 10012）；所选模型被供应商退役 → 提示重选模型（错误码 10013）。

### 3.16 新用户指引（FR-019，P2）

**描述**：账号**首次**注册并进入首页后，自动启动一次**分步高亮引导**——用遮罩高亮依次指向核心功能入口并配一句话说明，帮助新用户在 30 秒内建立"这个系统能干什么、东西在哪"的整体认知。**全程可跳过**，走完或跳过后不再自动弹出；个人中心提供重看入口。

**引导步骤编排**（5 步，按求职流程的推进顺序）：

| 步骤 | 高亮目标 | 说明要点 |
|---|---|---|
| 1/5 | 投递管理（侧栏入口） | 每一家投递都记在这里；支持表单一键录入、一句话解析、对话式录入三种方式 |
| 2/5 | JD 匹配分析 | 看到心仪 JD 粘贴进来，出匹配报告：评分 + 差距 + 准备建议 |
| 3/5 | AI 模拟面试 | 选一条投递记录发起模拟面试，AI 带着公司与岗位背景逐题发问、点评打分 |
| 4/5 | 八股陪练 / 错题本 | 笔试备战：答题即点评，答错自动进错题本并按 1/3/7/15 天安排复习 |
| 5/5 | 右上角用户菜单 → AI 配置 | **AI 功能的总开关**：在此填写供应商 Key 并选择模型；未配置时 AI 类功能不可用 |

**每步弹层元素**：步骤进度（如 `3/5`）、标题、一句话说明、按钮「下一步」与「跳过」（最后一步按钮为「完成」）。

**触发与标记规则**：

1. **触发时机**：账号首次注册成功后进入首页时自动启动；已走过或已跳过该引导的账号，之后登录**不再自动弹出**；
2. **标记存储**：点「完成」（走完最后一步）或任意一步点「跳过」，均视为已知晓，写入该账号的 `guide_done` 配置项（账号级，复用系统设置的读写接口，见数据库设计文档 §3.14 与接口文档 §3.12）；**不做服务端强制**，标记仅作前端判断依据；
3. **重看入口**：个人中心提供「重看新手指引」按钮，点击立即重新播放，**仅本次有效**，不修改 `guide_done` 标记；
4. **与其他需求的关系**：引导只**指向**功能入口，不代替实操——不自动创建投递、不代替 AI 配置（第 5 步仅说明"需先配置"）；引导期间系统其余功能可用，不锁定页面。

**异常场景**：高亮目标在当前布局中不存在（窗口过窄致侧栏折叠、页面元素未渲染完成）→ 该步自动跳过并继续下一步，不阻塞流程；引导过程刷新页面 → 视为未完成，下次进入首页重新开始（不做中断续播）。

**非目标**：不做强制分步（每步均可跳过）、不做帮助中心/图文教程页、不做按使用情况动态生成的条件性引导（先验证固定 5 步的效果）。

### 3.17 练习模式（FR-020，P2）

**命名口径**：练习模式在代码与数据结构中统一用 `drill` 前缀——表 `drill_topic` / `drill_attempt`、模式标识 `DRILL`、路由 `/drills`。**`practice` 在本项目中已专指「八股陪练」**（FR-009：`practice_service`、`/stream/practice-review`、前端 `/practice` 页面），两者不可混用，文档正文中「练习模式」一律指本节功能、「陪练」一律指 FR-009。

**描述**：把**同一道题反复练**的练习形态——用户自建「我的题目」（如自我介绍、某个项目的讲解、某道一直答不好的八股题），每练一遍给一次内容与表达点评，多遍之后给出**跨次进步对比**。与模拟面试的分工：模拟面试是"一场 N 题、题题不同"，练临场应变；练习模式是"一道题 N 遍"，练到流畅。

**处理流程**：

1. **建题**：手动写题面，或从错题本 / 面经条目 / 投递记录 JD / 简历**导入**（导入只记录来源，不复制来源内容）；
2. **练一遍**：作答（文字，或语音——见 FR-014）→ AI 给出 0~10 分 + 亮点 + 不足 + 参考要点；语音作答同时产出表达维度点评；
3. **再练**：同一道题可反复提交，每次独立留存（第几遍、作答内容、指标快照、得分、点评、提交时间）；
4. **看进步**：题目详情页按时间线展示历次记录，并给出**跨次对比**（如"第 3 遍 vs 第 1 遍：填充词 12→4、时长 95 秒→68 秒、停顿 3 处→1 处"）；
5. 题目可编辑、可归档——归档后不在默认列表展示，**历史记录保留**。

**规则**：

- 题目归属账号，账号间互不可见（与其余账号私有数据同口径）；
- 每题作答遍数不限；
- 跨次对比时界面提示**一次只关注一个指标**，避免"感觉有进步但说不清哪里变了"；
- 点评中的知识点与模拟面试同口径提示入错题本候选（见 FR-007）。

**异常场景**：点评生成中途失败 → 本次作答保留，可重试点评；题目归档后仍有历史记录可查。

**非目标**：不做公共题库式的题目分享、不做题目的 AI 批量自动生成（题目由用户建立或从既有数据导入）、不做多题连贯的成套练习（成套场景由模拟面试承担）。

### 3.18 校招情报（FR-021，P1）

**描述**：把多所高校就业网站发布的**宣讲会 / 双选会 / 岗位**三类信息汇聚到一处，跨源去重、检测变更、按画像排序，命中订阅规则即写站内提醒。解决的问题是"只盯本校会漏掉机会、多校逐个刷看不过来、宣讲会改期了不知道"——原有设计只把本校宣讲会搬上首页，信息范围与便利性都不够。

**信息范围与来源**：

| 项 | 说明 |
|---|---|
| 来源 | 高校就业网站公开页面（免登录即可访问）——国内高校就业网站集中在三家系统厂商：**91job**（江苏为主）、**云就业**、**才立方**，一套解析器可覆盖多校 |
| 组织方式 | **一厂商一解析器 + 一校一配置**：新增一所学校 = 新增一行源配置（学校名 / 系统类型 / 域名 / 参数），**不写代码** |
| 源管理 | 设置页维护源清单：新增 / 修改 / 启用停用 / 删除，并展示每个源的上次抓取时间与结果（成功 / 失败 / 受限） |
| 抓取频率 | 每日一次全量（并入 FR-013 的每日任务，全站执行一次）；设置页与校招情报页可**手动触发一次**（演示与调试用） |
| 单源隔离 | 任一源抓取失败只标记该源状态，不影响其余源，也不影响提醒等其他每日任务 |

**处理规则（纯规则实现，零 token、即时返回，不调 LLM）**：

| 处理 | 规则 |
|---|---|
| 跨源去重 | 按**去重指纹**判定是否为同一条信息（宣讲会/双选会 = 公司 + 标题 + 日期；岗位 = 公司 + 标题 + 城市）。同一场宣讲会在多所学校网站同时出现时**只保留一条**，来源记为多个站点 |
| 变更检测 | 内容指纹变化（时间 / 地点 / 专业要求等）→ 覆盖为最新值、标记**「已变更」**、并对订阅命中者推送提醒。**改期是真实高频事件**（宣讲会改期率约 25%），"改期不知道"是原有设计最大的信息漏损 |
| 过期归档 | 活动日期已过 → 标记过期；岗位过截止日期、或无截止日期且 30 天未再抓到 → 标记过期；过期超 90 天物理删除。**源抓取失败时不执行归档**，避免源故障导致数据被误清 |
| 匹配排序 | 按画像打分排序：目标城市命中 +30 / 目标方向关键词命中 +40 / 专业命中 +30（满分 100）。**信息缺失的维度不扣分也不隐藏**——避免"岗位没写专业要求就被判低分"这类失真，只让它在排序上自然靠后 |

**投喂通道（兜底）**：招聘信息不一定都发布在就业网站上（企业官网、公众号、群里转发）。用户可在校招情报页**粘贴 JD 文本**或**粘贴链接**，系统用 AI 抽取结构化字段后**返回预览**，确认后入库。预览不直接落库（与 Agent 写操作出确认卡片同口径：AI 抽取可能错字段，用户确认是最后一道关）。抽取失败降级为手动填表。**投喂记录为本账号私有**，其他账号完全不可见。

**订阅规则**：账号可建多条订阅规则（关键词 / 公司 / 城市 / 信息类型；**规则内不同维度之间为「与」，同维度多个值之间为「或」**，留空 = 该维度不限）。新信息入库或原信息发生变更时，逐条比对本账号启用中的规则，命中即写入**站内提醒**（复用现有提醒体系，概览与提醒列表自动可见，不新建推送通道），同一条信息同一天不重复提醒。**匹配范围限于公共信息与该账号自己的投喂记录**——不得命中其他账号的投喂内容（与全系统跨账号隔离口径一致）。

**业务打通**：

| 操作 | 行为 |
|---|---|
| 加入投递 | 跳投递新建表单并预填公司 / 岗位 / 渠道（= 来源站点）/ 备注（原文链接） |
| 分析匹配度 | 跳 JD 匹配分析页并预填岗位描述（投喂记录带原文摘录，自动抓取的记录提示需粘贴） |
| 已投递标记 | 卡片按「公司 + 岗位名」比对当前账号投递记录，命中显示"已投递" |

**异常场景**：某源解析失败 → 该源标记失败状态，源管理处提示"该源疑似失效"，其余源不受影响；抓取被站点拒绝（robots 禁止或持续 403）→ 标记为受限并**停止该源、不重试**；投喂抽取失败 → 提示原因并降级为手动填表；全部源均不可用时页面展示上次抓到的数据与抓取时间。

**合规要求**：本节功能的采集行为必须满足 NFR-016。

**非目标**：不做商业招聘平台抓取、不绕过登录 / 验证码 / 付费墙、不抓取与存储正文（只存元数据 + 原文链接）、不做 `.ics` 导出与手机日历同步、不做移动端适配、不做图片海报（长图招聘信息）多模态提取。

### 3.19 站内日历（FR-022，P2）

**描述**：校招情报页内的**月视图**，把与求职相关的时间节点集中展示，回答"这周 / 这个月有哪些安排"。经讨论确定**不做 `.ics` 导出与手机日历同步**，改为项目内自建日历。

**事件类型（一次请求返回四类）**：

| 事件 | 数据来源 | 说明 |
|---|---|---|
| 宣讲会 | 校招情报的宣讲会信息（`info_type = TALK`） | 按活动日期落格 |
| 双选会 | 校招情报的双选会信息（`info_type = FAIR`） | 按活动日期落格 |
| 笔试 | 当前账号状态为「待笔试」的投递记录的下一次时间 | 见 FR-002 / FR-004 |
| 面试 | 当前账号状态为「面试中」的投递记录的下一次时间 | 同上 |

**规则**：

1. 按区间查询（`start` / `end` 必填），**跨月查询一次返回四类事件**，避免前端并发拉取多个列表；空区间返回空数组，不报错；
2. 四类事件用不同颜色区分；点日期展开当日事件，点事件跳转对应详情（信息详情 / 投递详情）；
3. 日历内容 = **全站公共**的宣讲会 / 双选会 + **当前账号**的笔试 / 面试（与 4.1 数据归属一致，不带出其他账号的投递信息）。

**非目标**：不做日程提醒推送（提醒仍由 FR-013 的每日任务承担）、不提供"新建日程"（日历只展示既有数据，不成为第二套待办系统）。

## 4. 数据需求

### 4.1 核心数据字典（枚举口径，全系统统一）

**投递状态（application.status）**：

| 值 | 名称 | 说明 |
|---|---|---|
| APPLIED | 已投递 | 简历已投出，等待反馈（默认） |
| WRITTEN | 待笔试 | 已收到笔试通知 / 笔试流程中 |
| INTERVIEW | 面试中 | 进入面试流程（含多轮面试） |
| OFFER | 已获 offer | 收到录用意向/offer |
| CLOSED | 已结束 | 未通过 / 主动放弃 / offer 后终止（终态） |

**投递结束原因（application.close_reason）**：`FAILED` 未通过（笔试/面试被淘汰）/ `DECLINED` 主动放弃（拒 offer、不去面试等）/ `EXPIRED` 无消息（长期无进展，自己归档）。**仅当投递状态为 `CLOSED` 时有值**，该状态本身仍是终态。

**错题复习状态（wrong_question）**：档位 1/2/3/4（间隔 1/3/7/15 天）、MASTERED（已掌握，移出待复习池）。

**技术栈（question.stack，题库一级分类）**：`JAVA_BACKEND`（Java 后端）/ `PYTHON`（Python）/ `AI_AGENT`（AI 与大模型应用）/ `BACKEND_COMMON`（后端通用）/ `COMMON`（计算机通用基础）。

**领域（question.direction / interview_session.direction，题库二级分类）**：`JAVA`（Java 语言与集合）/ `JVM` / `CONCURRENCY`（Java 并发与多线程）/ `SPRING` / `MYSQL` / `REDIS` / `MQ`（消息队列）/ `NETWORK` / `OS` / `ALGO`（数据结构与算法）/ `DESIGN`（设计模式与架构）/ `PY_BASIC` / `PY_ASYNC` / `PY_WEB` / `LLM_BASIC` / `PROMPT` / `RAG` / `AGENT` / `GENERAL`（通用综合）。`stack` 与 `direction` 为**固定映射**（映射表见数据库设计文档 §5）；`GENERAL` 无对应 `stack`，仅用于模拟面试。

**题型（question.qtype）**：`SUBJECTIVE`（主观题，LLM 判定）/ `CHOICE`（客观题，规则判定）/ `SCENARIO`（场景题，LLM 按四维度评分）。

**面经条目来源（experience_item）**：LLM_EXTRACT（AI 提取）/ MANUAL（手动补充）。

**模拟面试会话状态（interview_session.status）**：ACTIVE（进行中）/ FINISHED（已结束并生成总结）。

**练习题目来源（drill_topic.source）**：`INTRO`（自我介绍）/ `RESUME`（简历项目）/ `WRONG`（错题本）/ `EXPERIENCE`（面经条目）/ `JD`（投递记录 JD）/ `CUSTOM`（手动新建）。

**语音指标数据质量（voice_metrics.quality）**：`OK`（正常分析）/ `TOO_SHORT`（作答不足 10 秒，不产出表达维度）/ `TEXT_ONLY`（纯文字作答，不产出表达维度）。

**账号角色（user.role）**：`USER`（普通用户）/ `ADMIN`（管理员）。本期不做权限差异，为后续管理功能预留。

**功能套餐（user.plan）**：`FREE`（免费）/ `PRO`（高级）。**本期预留字段，不启用**——所有功能对所有账号开放，为后续可能的高级功能预留扩展位。

**宣讲会/双选会类型（`campus_event.info_type`）**：`TALK` 宣讲会 / `FAIR` 双选会。

**岗位性质（`job_posting.job_type`）**：`CAMPUS` 校招 / `INTERN` 实习 / `SOCIAL` 社招。

**信息状态（`campus_event.status` / `job_posting.status`）**：`ACTIVE` 有效 / `CHANGED` 已变更（内容发生变化，如改期） / `EXPIRED` 已过期。

**就业网站系统类型（`crawl_source.system_type`）**：`91JOB`（91job）/ `BYSJY`（云就业）/ `JYSD`（才立方）。

**信息源抓取状态（`crawl_source.last_status`）**：`OK` 成功 / `FAILED` 失败 / `BLOCKED` 受限（robots 禁止或站点明确拒绝，停止抓取不重试）。

**岗位入库方式（`job_posting.ingest_source`）**：`AUTO` 自动抓取 / `FEED` 投喂。

**提醒类型（`reminder.reminder_type`）新增值**：`INFO_MATCH` 订阅命中（原有值：`FOLLOW_UP` 投递跟进 / `WRONG_QUESTION` 错题复习 / `INTERVIEW` 面试）。

**数据归属（账号私有 vs 公共）**：

| 归属 | 数据 | 规则 |
|---|---|---|
| **账号私有** | 投递记录、JD 分析报告、模拟面试会话与问答、面经与条目、陪练记录、错题、练习题目与记录、Agent 会话与消息、提醒、求职画像、系统设置、AI 供应商配置、**订阅规则、投喂的岗位记录** | 每条数据归属唯一账号，**其他账号完全不可见、不可访问、不可操作** |
| **公共** | 八股题库（`question`）、宣讲会/双选会（`campus_event`）、自动抓取的岗位（`job_posting` 中 `user_id = 0` 的记录）、抓取源配置（`crawl_source`） | 全站共享一份；题库由种子数据与 AI 生成题目构成，宣讲会/双选会与岗位由系统统一抓取 |
| **混合表（按归属字段区分）** | 岗位（`job_posting`） | 同表内两态：`user_id = 0` 为自动抓取的**公共岗位**，`user_id = <账号 id>` 为该账号**投喂的私有岗位**；查询时只取「公共 + 本账号」两类记录 |

**越权防护要求**：账号 A 访问账号 B 的资源 id（如投递、会话、报告）时，后端一律按"资源不存在"处理（返回 10002），**不得返回数据内容、不得暴露该资源是否存在**。

### 4.2 数据规模估计

| 数据 | 量级 | 说明 |
|---|---|---|
| 账号 | 个位数至十位数 | 单实例部署，账号数少 |
| 投递记录 | 数百条/账号 | 秋招季个人使用 |
| 八股题库 | 内置 **585 题**（5 个技术栈 / 18 个领域 / 场景题 152 道），可持续扩充 | 种子题库随仓库发布，**全站共享**；导入按 `content` upsert，题量可随版本递增 |
| 错题 | 数百条/账号 | 滚动更新，已掌握可删 |
| 宣讲会 / 双选会 | 数百至数千条（全站公共） | 多校多源聚合、跨源去重后；过期超 90 天物理删除，存量有上界 |
| 岗位 | 公共数百至数千条 + 投喂数十条/账号 | 自动抓取为公共数据，投喂记录按账号隔离 |
| 练习题目 / 练习记录 | 题数十条/账号，记录数千条/账号 | 同一道题反复练、逐次留存（含表达力指标快照），见 FR-020 |

| Agent 对话 | 数千条消息/账号 | 单库 MySQL 无压力 |
| 头像文件 | ≤ 256×256 / 张，数十 KB | 存本机文件目录，库内只存路径 |

MySQL 8.0 单库完全满足；无需缓存层，直接 SQL 查询（全表扫描在此量级下无性能问题）。

## 5. 非功能需求

### 5.1 性能（NFR-001~004，低延迟为最高优先级）

| 编号 | 指标 | 量化目标 | 测量方式 |
|---|---|---|---|
| NFR-001 | AI 回复首字延迟 | < 2s，之后逐 token 流式（SSE） | 人工计时/日志埋点 |
| NFR-002 | 语音转写延迟 | < 1.5s/句（VAD 切出的 3~15s 音频片段；本地模型实测约 600ms 出字） | 人工计时 |
| NFR-003 | 普通 API 响应 | < 200ms（不含 LLM 调用） | 接口压测/计时 |
| NFR-004 | 本地页面操作响应 | < 300ms | 浏览器 DevTools |

**低延迟技术措施（设计与实现必须遵守）**：

1. 所有 LLM 输出走 SSE 流式，**禁止等完整回复再渲染**；
2. 语音按 **VAD 切句逐句识别**（长时长交互由多句拼成），不做整场录音的离线转写；ASR 走本地进程内模型，无网络往返；
3. Agent 执行动作采用**乐观更新**：一句话录入投递，前端先出确认卡片，后端确认后刷新列表；
4. 前端 SPA 无整页刷新，流式文本打字机渲染；
5. 定时任务后台线程执行，不阻塞任何请求；
6. 画像/系统 prompt 精简（控制在 1500 token 内），减少输入 token 拖慢首字；
7. SSE 连接建立后服务端立即推送开始事件（"正在分析…"状态文案），界面 300ms 内出反馈，覆盖 LLM 首字前的等待感知。

### 5.2 可用性（NFR-005~007）

| 编号 | 要求 |
|---|---|
| NFR-005 | LLM 异常兜底：调用失败 → 前端明确提示 + 一键重试；任何 LLM 失败不得导致页面白屏或数据丢失 |
| NFR-006 | 降级可用：断网/无 Key 时，投递管理、错题列表、面经检索等纯数据功能完全可用 |
| NFR-007 | 定时任务失败不影响主流程；信息源抓取失败静默降级（保留上次数据 + 显示抓取时间 + 标记该源状态） |

### 5.3 安全（NFR-008~010、NFR-013~016）

> 编号按主题分配，不按章节顺序连续：NFR-011 为兼容性、NFR-012 为可维护性，安全主题的新增条目顺延为 NFR-013~016。

| 编号 | 要求 |
|---|---|
| NFR-008 | **密钥安全**：AI 供应商 Key 与讯飞语音 Key（选用云端 ASR 时）**按账号加密存储**（Fernet 对称加密，主密钥存 .env 且已 gitignore）；密钥任何情况下不出现在代码、前端、日志中；接口**永不回显明文**，仅返回"是否已配置"布尔值。FunASR 本地与 edge-tts 无需密钥 |
| NFR-009 | 全部数据库访问经 SQLAlchemy 参数化查询，禁止字符串拼接 SQL（防注入） |
| NFR-010 | 前端渲染 LLM 输出与用户输入一律转义/使用安全渲染，防 XSS；后端接口做输入长度与类型校验 |
| NFR-013 | **认证安全**：密码以 bcrypt 哈希存储（不可逆）；JWT 签名密钥存 .env；登录失败连续 5 次锁定 5 分钟；登录失败提示不区分"用户名不存在 / 密码错误"（防用户名枚举）；修改密码后此前签发的 Token 全部作废 |
| NFR-014 | **数据隔离**：账号私有数据的读写**强制携带当前登录账号的 `user_id` 条件**（由服务层从登录态取得，禁止由前端参数指定归属）；跨账号访问按"资源不存在"处理（10002），不泄露资源存在性 |
| NFR-015 | **上传安全**：头像上传校验文件类型（仅 jpg/jpeg/png/webp）与体积（原图 ≤2MB）；文件名由服务端重命名（不使用用户提供的原始文件名，防路径穿越） |
| NFR-016 | **信息采集合规**（FR-021 的采集行为必须满足；按**合规组件统一实现**，不散落在各解析器中，便于单点修改与独立测试）：①请求携带明确的 UA 标识与用途说明（`JobHunterBot/1.0 (+个人求职助手；非商业自用)`）；②抓取前检查目标站点 robots，**读不到或明确禁止则跳过该源**并标记受限；③同域请求间隔 ≥ 2 秒、每源每日全量 1 次，遇 429 立即暂停、遇持续 403 停止该源**不重试**；④**只采集公开的岗位与活动元数据 + 原文链接**，不抓取不存储网页正文，不采集任何个人信息；⑤数据仅本机自用，**不对外提供、不做二次分发**；⑥每源保留最近一次抓取时间与结果状态，可自证访问频率 |

- 分辨率：≥ 1280×720 完整显示；

**模型列表动态更新（保证"最新可用版本"）**：

1. OpenAI 兼容协议提供 `GET /models` 端点，返回该供应商当前全部可用模型；

**其他约定**：

- 默认模型：DeepSeek deepseek-flash（V4.1 Flash，内置思考/非思考模式）；深度分析场景可配置带推理能力的模型（配置项，默认仍用 flash 保证延迟）；
- 切换方式：AI 配置页选择供应商与模型并填写对应 Key，保存后可一键切换生效（见 FR-018）；
- 免费方案：未开通付费服务时切换至提供免费额度的供应商（智谱 Flash 系列、通义千问、豆包等）；免费模型有限速，请求失败走统一 LLM 兜底（重试 + 提示）；
- 全部流式（stream=True），超时与重试策略见系统设计文档。

### 6.2 语音服务（P2）

**ASR（语音识别）**：

- **默认：FunASR 本地流式模型**（`paraformer-zh-streaming`，进程内运行，CPU 可跑，实测约 600ms 出字）；**不限时长、零费用、不出网**，答辩断网可用；
- 备选：讯飞实时语音转写（WebSocket 长连接，需 AppID / APIKey / APISecret 且需实名认证）；
- **首次使用需联网下载一次模型**（AutoModel 自动从 ModelScope 拉取，约数百 MB），之后离线可用。

**TTS（语音合成）**：

- **默认：edge-tts**（微软 Edge 在线语音接口的 Python 封装，免费、无需注册），中文音色 20+（晓晓 / 云希 / 云扬等），自然度显著优于浏览器 `speechSynthesis`；
- 链路：后端合成音频 → 前端播放器；合成结果按「文本 + 音色」缓存，重复播报免二次合成；
- 局限：不支持声音克隆、情绪表现有限（课设场景够用）；如需克隆/更强情感，后续可扩展豆包语音（约 150 元/音色/年）。

**供应商抽象**：`asr_client` / `tts_client` 抽象基类 + 默认实现（FunASR / edge-tts）+ 备选实现（讯飞），设置页可切换，按账号保存。

### 6.3 高校就业信息源（多源采集）

- 用途：每日聚合宣讲会 / 双选会 / 岗位公开信息（见 FR-021）；
- 目标：高校就业网站的公开页面——国内高校就业网站集中在三家系统厂商（**91job**（江苏为主）/ **云就业** / **才立方**），**按校配置源清单**（设置页维护），站点与参数不写死在代码中；
- 技术：`httpx` + `lxml` 解析（三家均为服务端渲染页面或免登录 JSON 接口），**不引入浏览器内核**；
- 约束：遵 NFR-016——只抓公开列表与详情元数据、不做登录、不绕过反爬与验证码、同域限频 ≥ 2 秒、每源每日 1 次；**单源失败静默降级**，保留上次数据并标记该源状态。

## 7. 范围边界（明确不做）

| 不做项 | 原因 |
|---|---|
| 校园跑腿 / 二手交易 / 财务记账 | 与求职主线无关 |
| **商业招聘平台抓取**（BOSS 直聘 / 智联 / 前程无忧 / 猎聘等） | 登录墙 + 字体加密 + 验证码，技术手段需绕过防护；且已有不利判例（北京互联网法院 2026 年职场平台数据案：「避开技术防护」系统性抓取 + 「对外提供」构成不正当竞争）。**高校就业网站公开信息的多源聚合（FR-021）不在此列**——公开页面、免登录、低频、个人自用、不对外提供 |
| 绕过登录 / 验证码 / 付费墙的任何手段 | 合规红线，且可能触及《刑法》第 285 条（非法获取计算机信息系统数据） |
| 抓取并存储网页正文 | 只存元数据 + 原文链接，正文一律跳原文，避免"实质性替代"（见 NFR-016） |
| `.ics` 导出与手机日历同步 | 经讨论确定改为**项目内自建日历**（FR-022），不做导出 |
| 邮箱自动接入 | 作为"后续规划"方向保留一句，不在本期范围 |
| LangChain / 框架化 Agent | 课程要求体现手写 Agent 能力（意图路由+工具注册+画像记忆） |
| 整场录音的离线转写与超大本地模型（Whisper large 等） | 部署重、CPU 推理慢；改用 **FunASR 流式短句识别**（轻量、进程内、约数百 MB） |
| 声音克隆 / 情绪化配音 | 需 GPU 或付费云服务，超出课设范围；TTS 用 edge-tts 内置音色 |
| 实时语音提醒（边说边提示"说慢点"等） | 一期只做**事后**表达分析；实时提醒需前端实时处理音频流，列为后续可选增强 |
| 情绪识别与情感计算 | 静音与语速可测、情绪不可测；不引入微表情与语调情感分析 |
| 发音 / 声学评分 | 不做音准、清晰度、口音评价——求职面试的瓶颈不在发音 |
| 多人对话与打断处理 | 仅单人作答场景 |
| 原始音频留存 | 音频仅在转写期间存在，转写完成即丢弃；库内只保留文本与指标快照 |
| 第三方登录（OAuth：微信 / GitHub 等） | 需外网回调与三方应用审核，本机工具无必要 |
| 邮箱验证 / 找回密码 | 本机无邮件服务；密码可由用户凭原密码在个人中心自行修改 |
| 付费订阅与权限分级 | `role` / `plan` 字段仅作**预留**，本期不做付费、不做管理后台 |
| 简历自动生成/投递机器人 | 涉及第三方网站自动化，合规风险 |
| 移动端 App 与移动端适配 | 项目定位为桌面 Web（本机运行），**只做电脑端**——不做移动端 App，也不针对手机 / 平板做适配 |
| 图片海报（长图招聘信息）的多模态提取 | 依赖视觉模型，列为后续规划 |
