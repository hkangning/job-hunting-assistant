## 1. 总则

1. **步骤制，不预设时间节点**：每步明确"做什么 → 产出 → 验收标准"，验收通过才进入下一步骤。
2. **文档先行**：动代码前确认对应文档（需求/设计/数据库/接口）已定稿；发现文档问题先改文档再改代码。
3. **测试随开发**：每步代码完成后跑对应测试用例（编号对应测试计划），全绿才验收。
4. **前后端并行**：前后端以接口文档为协作契约并行开发；后端接口先行可用（前端可用 mock 数据联调）。
5. **范围控制**：不实现文档中未约定的功能；语音为 P2 增强项（步骤 10），不阻塞主线。

## 4. 各步骤详情

### 步骤 1：工程骨架 + 数据库落地

- **后端（胡康宁）**：按项目结构文档建目录；15 张表 ORM 模型 + enums.py（口径=数据库设计文档第 5 章）；database.py（WAL+外键）；config.py；main.py（lifespan：建库/导种子/定时器注册）；health 路由 + 统一响应体 + 异常处理（exceptions.py 全量错误码）；种子题库 questions.json（Java/MySQL/网络/OS 各 ≥30 题）
- **前端（卢世君）**：Vite 工程 + 路由表 + 侧边导航布局 + request.js（axios 拦截）+ Element Plus 接入
- **测试（卢世君）**：conftest.py（测试库 + FakeLLMProvider + 依赖注入点）

**产出**：两端可启动，`/health` 通，15 张表落库。

**验收**：后端 `uvicorn` 启动无报错；`sqlite3` 查 15 张表存在；前端 9 个路由可导航（页面占位）；`pytest` 通过。

### 步骤 2：投递管理 + 今日概览

- **后端（胡康宁）**：application 全部接口（CRUD/状态流转/批量导入/模板/趋势）；overview 聚合接口（纯 SQL 规则，错题与宣讲会区块此步返回空占位）
- **前端（卢世君）**：投递看板（Kanban 拖拽流转）+ 概览页
- **测试（卢世君）**：TC-01~04、TC-26、TC-27、TC-46

**产出**：投递数据闭环可用（表单/看板/导入/流转），概览页展示统计与跟进提醒。

**验收**：用例全绿；页面手工：新增→看板流转→概览统计一致。

### 步骤 3：用户画像 + 系统设置

- **后端（胡康宁）**：profile/settings 接口；**供应商注册表（deepseek/zhipu/kimi/siliconflow/custom）+ 连通性测试接口**（llm_provider.py + /settings/llm-test）
- **前端（卢世君）**：设置页（供应商选择 + Key 输入 + 连通性测试按钮 + 画像编辑表单 + 开关项）

### 步骤 4：JD 匹配分析（首个 SSE 链路）

- **后端（胡康宁）**：llm_client（stream_chat/chat_json/test_connection/超时/重试）；prompts.py 首批模板（JD 五段结构）；/stream/jd-analysis 端点；报告落库与列表/详情

### 步骤 5：八股陪练 + 错题本

## 5. 风险清单

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| LLM 供应商网络不稳/限流/欠费 | AI 功能全挂，演示受影响 | 重试+兜底提示；演示前检查余额/配额；**演示机热点兜底**；预留"预生成演示数据"方案 |
| 免费供应商限速严重 | 使用免费方案时 AI 响应慢/频繁失败 | 统一兜底（重试+提示）；演示环境优先配置有额度的供应商；设置页一键切换 |
| 讯飞注册/审核周期长 | 步骤 10 延迟 | P2 不阻塞主线；先用文字版验收；阿里云作备选 |
| 学校就业网改版/反爬 | 抓取失败 | 失败静默降级（设计已含）；手动录入宣讲会兜底（campus_event 接口预留） |
| 前后端协作冲突（git） | 联调返工 | 接口文档先行定稿；后端先出可 mock 的接口；每日合并一次 |
| SQLite 并发写锁 | 偶发 500 | WAL 模式；写事务最小化；LLM 不在事务内 |
| LLM 输出格式漂移（不按五段/JSON 出） | 解析失败 | 格式校验+降级路径（设计第 7 章）；判定类 JSON 重试 1 次 |
| 演示环境无外网 | AI 功能瘫痪 | 手机热点；演示前完整预演一次 |

## 6. 验收演示预案

**演示脚本结构**（正式验收演示前按此完整预演）：

1. **开场**（30s）：一句话定位——"覆盖投递到复盘全流程的个人求职助手，AI 嵌入每个操作而不是套壳聊天"；
2. **今日概览**：展示四个提醒区块（提前造好数据：明日面试、3 天前投递、到期错题）；
3. **投递三方式**：表单录入 → 悬浮球一句话录入（确认卡片）→ 批量导入（演示模板+一行非法行报错）；
4. **JD 分析**：粘贴真实 JD → 流式五段报告（边讲：SSE 流式，首字 2 秒内）；
5. **模拟面试**：发起会话 → 语音作答 1~2 题（P2 完成后）→ 逐题点评 → 总结报告；
6. **陪练与错题**：答 1 题（故意答差）→ 自动入错题本 → AI 抽问；
7. **兜底演示（加分项）**：展示一次断网/错 Key 下的错误提示与重试——体现工程健壮性；
8. **收尾**（30s）：技术亮点一句话——手写 Agent、SSE 全链路、多供应商可切换、LLM 全 mock 测试、文档体系完整。

**数据准备**：验收演示前在演示环境预置一套数据（投递 10+ 条覆盖各状态、面经 3 篇、错题 5 条、模拟面试 2 场），确保每个区块打开即有内容。

**应急预案**：外网故障 → 热点；LLM 限流 → 顺势演示"兜底提示+重试"环节；数据库损坏 → 备份文件恢复（演示前复制 app.db）。
