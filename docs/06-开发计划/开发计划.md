## 1. 总则

1. **步骤制，不设日期节点**：每步明确"做什么 → 产出 → 验收标准"，验收通过才进入下一步骤；开发周期预算 ≥2 个月，节奏自行把握，宁慢勿赶。
2. **阶段制 + 里程碑**：21 个步骤归入 5 个阶段，每阶段结束设里程碑验收点（见第 3 节），阶段产物固化后再进入下一阶段。
3. **文档先行**：动代码前确认对应文档（需求/设计/数据库/接口）已定稿；发现文档问题先改文档再改代码。
4. **测试随开发**：每步代码完成后跑对应测试用例（编号对应测试计划），全绿才验收。
5. **质量基线（每步验收时执行）**：①对应测试用例全绿；②接口文档状态标注同步更新；③手工验收有记录（页面截图/结果登记）；④代码走查一次（异常处理、边界条件、注释规范）。
6. **前后端并行**：前后端以接口文档为协作契约并行开发；后端接口先行可用（前端可用 mock 数据联调）。
7. **范围控制**：不实现文档中未约定的功能；语音为 P2 增强项（阶段四），不阻塞主线。

## 5. 各步骤详情

### 步骤 1：工程骨架

- **后端（胡康宁）**：按项目结构文档建目录与依赖；config.py；main.py（lifespan 预留建库/导种子/定时器注册）；health 路由 + 统一响应体 + exceptions.py（全量错误码注册）
- **前端（卢世君）**：Vite 工程 + 路由表 + 侧边导航布局 + request.js（axios 拦截器）+ Element Plus 接入
- **测试（卢世君）**：conftest.py（独立测试库 + FakeLLMProvider 占位 + 依赖注入点）

**产出**：两端可启动，`/health` 通，统一响应体与异常处理就位。

**验收**：后端 uvicorn 启动无报错；前端 9 个路由可导航（页面占位）；pytest 骨架通过；统一响应体四态手测正常。

### 步骤 2：数据库落地

- **后端（胡康宁）**：15 张表 ORM 模型（口径=数据库设计文档第 5 章枚举表）+ enums.py；database.py（WAL+外键开启）；建库脚本；种子题库 questions.json（Java/MySQL/网络/OS 各 ≥30 题）
- **测试（卢世君）**：建表冒烟——启动后校验 15 表存在、字段与索引一致、枚举默认值正确

**产出**：空库一键初始化，种子题库入库。

**验收**：sqlite3 查 15 张表存在且字段符合设计文档；questions 表种子数据 ≥120 题。

## 7. 验收演示预案

**演示脚本结构**（正式验收演示前按此完整预演）：

1. **开场**（30s）：一句话定位——"覆盖投递到复盘全流程的个人求职助手，AI 嵌入每个操作而不是套壳聊天"；
2. **今日概览**：展示四个提醒区块（提前造好数据：明日面试、3 天前投递、到期错题）；
3. **投递三方式**：表单录入 → 悬浮球一句话录入（确认卡片）→ 批量导入（演示模板+一行非法行报错）；
4. **JD 分析**：粘贴真实 JD → 流式五段报告（边讲：SSE 流式，首字 2 秒内）；
5. **模拟面试**：发起会话 → 语音作答 1~2 题（P2 完成后）→ 逐题点评 → 总结报告；
6. **陪练与错题**：答 1 题（故意答差）→ 自动入错题本 → AI 抽问；
7. **兜底演示（加分项）**：展示一次断网/错 Key 下的错误提示与重试——体现工程健壮性；
8. **收尾**（30s）：技术亮点一句话——手写 Agent、SSE 全链路、多供应商+模型级可切换、LLM 全 mock 测试、文档体系完整。

**数据准备**：验收演示前在演示环境预置一套数据（投递 10+ 条覆盖各状态、面经 3 篇、错题 5 条、模拟面试 2 场），确保每个区块打开即有内容。

**应急预案**：外网故障 → 热点；LLM 限流 → 顺势演示"兜底提示+重试"环节；数据库损坏 → 备份文件恢复（演示前复制 app.db）。
