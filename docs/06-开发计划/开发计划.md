## 1. 总则

1. **步骤制，不设日期节点**：每步明确"做什么 → 产出 → 验收标准"，验收通过才进入下一步骤；开发周期预算 ≥2 个月，节奏自行把握，宁慢勿赶。
2. **阶段制 + 里程碑**：29 个步骤归入 5 个阶段，每阶段结束设里程碑验收点（见第 3 节），阶段产物固化后再进入下一阶段。
3. **文档先行**：动代码前确认对应文档（需求/设计/数据库/接口）已定稿；发现文档问题先改文档再改代码。
4. **测试随开发**：每步代码完成后跑对应测试用例（编号对应测试计划），全绿才验收。
5. **质量基线（每步验收时执行）**：①对应测试用例全绿；②接口文档状态标注同步更新；③手工验收有记录（页面截图/结果登记）；④代码走查一次（异常处理、边界条件、注释规范）；⑤**用户视角成果对照**——按该步「用户可见成果」段落确认：界面类成果须实际打开页面走一遍并留截图，纯后端步骤须给出可现场演示的验证方式（Swagger / Postman 调用）。
6. **前后端并行**：前后端以接口文档为协作契约并行开发；后端接口先行可用（前端可用 mock 数据联调）。
7. **范围控制**：不实现文档中未约定的功能；语音、表达力分析与练习模式为 P2 增强项（阶段四），不阻塞主线。

## 6. 风险清单

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| LLM 供应商网络不稳/限流/欠费 | AI 功能全挂，演示受影响 | 重试+兜底提示；演示前检查余额/配额；**演示机热点兜底**；预留"预生成演示数据"方案 |
| 长周期节奏松弛（≥2 个月跨度） | 中后期动力下降、临近截止赶工 | 5 个里程碑验收点强制阶段固化；每步验收三件套+质量基线；阶段完成做一次小复盘 |
| 前后端进度错位（一方慢导致联调等待） | 步骤阻塞 | 后端接口先行+mock 联调；每步验收前先对齐双方进度 |
| 本地语音模型首次下载失败 / 推理环境装不上 | 步骤 24 延迟 | P2 不阻塞主线；先用文字版验收；设置页切 `asr_provider=xunfei` 云端备用 |
| 本地模型依赖体积大（funasr 依赖 torch，venv 膨胀数 GB） | 环境搭建慢、磁盘占用高 | 依赖**仅在步骤 24 落地**（前 23 步不装）；模型首次联网下载（数百 MB）后本地缓存，**不入仓库** |
| 表达力指标算法口径调整 | 历史记录与新记录不可比，跨次进步曲线失真 | 指标带 `version` 标识，**跨版本记录不参与对比**（宁可少展示一次对比）；口径变更时同步修订 SRS 与系统设计 |
| 就业网站点改版导致解析失效 | 单个源数据断流 | **一厂商一解析器 + 单源隔离**：失败只标记该源状态（`last_status`），其余源与处理层不受影响；本地快照 fixture 可离线复现解析失败；界面提示"该源疑似失效" |
| 目标站点明确禁止抓取（robots 禁止 / 持续 403） | 该源不可用 | 合规组件按 robots 与状态码跳过并标记 `BLOCKED`，不重试；该源覆盖的学校改由**投喂通道**兜底（粘贴 JD / 活动信息经 AI 抽取入库） |
| 岗位信息来源不足（部分源岗位模块不开放） | 岗位库稀疏、匹配排序无数据可排 | 投喂通道兜底（本就是设计的一部分）；匹配打分对字段缺失不扣分也不隐藏 |
| 校招情报模块体量偏大（拆为 3 步） | 阶段三周期拉长 | 按步骤 21 → 22 → 23 顺序推进：步骤 21 先行交付多源宣讲会能力，页面与订阅功能分批联调 |
| 前后端协作冲突（git） | 联调返工 | 接口文档先行定稿；后端先出可 mock 的接口；每步骤结束合并一次 |
| 数据库连接空闲断开（MySQL `wait_timeout`） | 偶发 500 / 连接丢失 | 引擎 `pool_pre_ping`（取连接前探活）+ `pool_recycle=3600`（早于 MySQL 默认 `wait_timeout`）主动回收；LLM 调用不在事务内，长耗时请求不占连接 |
| LLM 输出格式漂移（不按五段/JSON 出） | 解析失败 | 格式校验+降级路径（设计第 7 章）；判定类 JSON 重试 1 次 |
| 演示环境无外网 | AI 功能瘫痪 | 手机热点；演示前完整预演一次；**语音链路已脱网**（本地 ASR + TTS 缓存），断网仍可演示语音作答 |

## 7. 验收演示预案

**演示脚本结构**（正式验收演示前按此完整预演）：

1. **开场**（30s）：一句话定位——"覆盖投递到复盘全流程的个人求职助手，AI 嵌入每个操作而不是套壳聊天"；
2. **入场与账号**（40s）：打开系统播出场动画 → 登录（勾选 30 天免登录）→ 进概览；顺带展示右上角用户菜单与个人中心（头像/画像/改密入口）；**现场注册一个新账号**触发新手指引（走 2 步后点「跳过」）；
3. **今日概览 + 校招情报**：展示四个提醒区块（提前造好数据：明日面试、3 天前投递、到期错题）+ **校招情报区块**（临近宣讲会含 1 条「已变更」、匹配度最高岗位、命中订阅计数）；点进「校招情报」页展示三类信息 Tab（含跨源去重后的一条）与**月历视图**（宣讲会 / 双选会 / 笔试 / 面试四类同屏）；
4. **投递三方式**：表单录入 → 悬浮球一句话录入（确认卡片）→ 批量导入（演示模板+一行非法行报错）；
5. **JD 分析**：粘贴真实 JD → 流式五段报告（边讲：SSE 流式，首字 2 秒内）；
6. **模拟面试**：发起会话 → **语音连续作答**（说完停顿自动断句转写、累积成段）→ **提交后指标卡片即时展示**（语速 / 填充词 / 停顿）→ 逐题点评（含一句音色播报）→ 总结报告；
7. **练习模式**：把刚才答得最差的一题存为「我的题目」→ 连练 2 遍 → 题目详情页展示**跨次进步对比**（填充词 / 时长 / 停顿三项变化）；
8. **陪练与错题**：选「面试官深挖」开一场（前两轮正常答、第三轮故意答不上）→ 展示**逐层追问**（依据 → 边界 → 取舍）与断点记录 → 结算页看综合分 / 断点回顾 / 参考答案 + **掌握度变化** → 未通过自动入错题本 → AI 抽问；
9. **兜底演示（加分项）**：展示一次断网/错 Key 下的错误提示与重试——体现工程健壮性；
10. **收尾**（30s）：技术亮点一句话——手写 Agent、SSE 全链路、**多账号数据隔离**、多供应商+模型级可切换、**多源校招信息聚合（合规采集：UA 标识 / robots 检查 / 限频）**、LLM 全 mock 测试、文档体系完整。

**数据准备**：验收演示前在演示环境预置**演示账号**（含已配置的 AI 供应商 Key）与一套数据（投递 10+ 条覆盖各状态、面经 3 篇、错题 5 条、模拟面试 2 场、**练习题目 3 条其中 1 条已练满 2 遍带跨次对比**、**校招信息：宣讲会 4 条其中 1 条已变更 1 条跨两源重复、岗位 6 条含 1 条投喂 1 条已投递标记、订阅规则 2 条、信息源 3 个**），确保登录后每个区块打开即有内容。

**应急预案**：外网故障 → 热点；LLM 限流 → 顺势演示"兜底提示+重试"环节；数据库损坏 → 备份恢复（演示前用 `mysqldump` 导出 `job_hunter` 库留档，异常时导回）。
