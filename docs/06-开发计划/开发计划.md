## 1. 总则

1. **步骤制，不设日期节点**：每步明确"做什么 → 产出 → 验收标准"，验收通过才进入下一步骤；开发周期预算 ≥2 个月，节奏自行把握，宁慢勿赶。
2. **阶段制 + 里程碑**：25 个步骤归入 5 个阶段，每阶段结束设里程碑验收点（见第 3 节），阶段产物固化后再进入下一阶段。
3. **文档先行**：动代码前确认对应文档（需求/设计/数据库/接口）已定稿；发现文档问题先改文档再改代码。
4. **测试随开发**：每步代码完成后跑对应测试用例（编号对应测试计划），全绿才验收。
5. **质量基线（每步验收时执行）**：①对应测试用例全绿；②接口文档状态标注同步更新；③手工验收有记录（页面截图/结果登记）；④代码走查一次（异常处理、边界条件、注释规范）；⑤**用户视角成果对照**——按该步「用户可见成果」段落确认：界面类成果须实际打开页面走一遍并留截图，纯后端步骤须给出可现场演示的验证方式（Swagger / Postman 调用）。
6. **前后端并行**：前后端以接口文档为协作契约并行开发；后端接口先行可用（前端可用 mock 数据联调）。
7. **范围控制**：不实现文档中未约定的功能；语音为 P2 增强项（阶段四），不阻塞主线。

## 5. 各步骤详情

### 步骤 1：工程骨架

- **后端（胡康宁）**：按项目结构文档建目录与依赖；config.py；main.py（lifespan 预留建库/导种子/定时器注册）；health 路由 + 统一响应体 + exceptions.py（全量错误码注册）
- **前端（卢世君）**：Vite 工程 + 路由表 + 侧边导航布局 + request.js（axios 拦截器）+ Element Plus 接入
- **测试（卢世君）**：conftest.py（独立测试库 + FakeLLMProvider 占位 + 依赖注入点）

**产出**：两端可启动，`/health` 通，统一响应体与异常处理就位。

**用户可见成果**：**界面无变化**（工程打底）。前端 9 个页面已可点击导航（均为占位内容），后端 `/health` 返回统一响应体——架子搭起来了，业务功能从下一步开始长。

**验收**：后端 uvicorn 启动无报错；前端 9 个路由可导航（页面占位）；pytest 骨架通过；统一响应体四态手测正常。

### 步骤 2：数据库落地

- **后端（胡康宁）**：15 张表 ORM 模型（口径=数据库设计文档第 5 章枚举表）+ enums.py；database.py（WAL+外键开启）；建库脚本；种子题库 questions.json（Java/MySQL/网络/OS 各 ≥30 题）
- **测试（卢世君）**：建表冒烟——启动后校验 15 表存在、字段与索引一致、枚举默认值正确

**产出**：空库一键初始化，种子题库入库。

**用户可见成果**：**界面无变化**（数据地基）。15 张表一次建好，128 道八股题（Java / MySQL / 网络 / OS 四方向）随首次启动自动入库，为后续陪练抽题、错题本备好题库；成果可用 sqlite3 或数据库管理工具直接查看。

**验收**：sqlite3 查 15 张表存在且字段符合设计文档；question 表种子数据 ≥120 题。

### 步骤 3：投递管理（后端）

- **后端（胡康宁）**：application 全部接口（CRUD/状态流转/批量导入/模板下载/趋势统计）；导入解析（xlsx/csv 行级错误不中断）
- **测试（卢世君）**：TC-01~04（服务层单元测试，FakeLLM 无关）

**产出**：投递数据接口层完整，可直接用 Postman 验证。

**用户可见成果**：**界面无变化**（纯后端）。打开 Swagger 页（`/docs`）即可现场演示完整投递管理：新增投递 → 状态流转（非法流转会被拒绝并提示）→ 下载模板→填写→批量导入（错误行逐行说明原因）→ 趋势统计；可视化的看板界面在步骤 4 呈现。

## 6. 风险清单

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| LLM 供应商网络不稳/限流/欠费 | AI 功能全挂，演示受影响 | 重试+兜底提示；演示前检查余额/配额；**演示机热点兜底**；预留"预生成演示数据"方案 |
| 免费供应商限速严重 | 使用免费方案时 AI 响应慢/频繁失败 | 统一兜底（重试+提示）；演示环境优先配置有额度的供应商；设置页一键切换 |
| 长周期节奏松弛（≥2 个月跨度） | 中后期动力下降、临近截止赶工 | 5 个里程碑验收点强制阶段固化；每步验收三件套+质量基线；阶段完成做一次小复盘 |
| 前后端进度错位（一方慢导致联调等待） | 步骤阻塞 | 后端接口先行+mock 联调；每步验收前先对齐双方进度 |
| 本地语音模型首次下载失败 / 推理环境装不上 | 步骤 22 延迟 | P2 不阻塞主线；先用文字版验收；设置页切 `asr_provider=xunfei` 云端备用 |
| 本地模型依赖体积大（funasr 依赖 torch，venv 膨胀数 GB） | 环境搭建慢、磁盘占用高 | 依赖**仅在步骤 22 落地**（前 21 步不装）；模型首次联网下载（数百 MB）后本地缓存，**不入仓库** |
| 学校就业网改版/反爬 | 抓取失败 | 失败静默降级（设计已含）；手动录入宣讲会兜底（campus_event 接口预留） |
| 前后端协作冲突（git） | 联调返工 | 接口文档先行定稿；后端先出可 mock 的接口；每步骤结束合并一次 |
| SQLite 并发写锁 | 偶发 500 | WAL 模式；写事务最小化；LLM 不在事务内 |
| LLM 输出格式漂移（不按五段/JSON 出） | 解析失败 | 格式校验+降级路径（设计第 7 章）；判定类 JSON 重试 1 次 |
| 演示环境无外网 | AI 功能瘫痪 | 手机热点；演示前完整预演一次；**语音链路已脱网**（本地 ASR + TTS 缓存），断网仍可演示语音作答 |

## 7. 验收演示预案

**演示脚本结构**（正式验收演示前按此完整预演）：

1. **开场**（30s）：一句话定位——"覆盖投递到复盘全流程的个人求职助手，AI 嵌入每个操作而不是套壳聊天"；
2. **入场与账号**（40s）：打开系统播出场动画 → 登录（勾选 30 天免登录）→ 进概览；顺带展示右上角用户菜单与个人中心（头像/画像/改密入口）；**现场注册一个新账号**触发新手指引（走 2 步后点「跳过」）；
3. **今日概览**：展示四个提醒区块（提前造好数据：明日面试、3 天前投递、到期错题）；
4. **投递三方式**：表单录入 → 悬浮球一句话录入（确认卡片）→ 批量导入（演示模板+一行非法行报错）；
5. **JD 分析**：粘贴真实 JD → 流式五段报告（边讲：SSE 流式，首字 2 秒内）；
6. **模拟面试**：发起会话 → **语音连续作答**（说完停顿自动断句转写、累积成段）→ 逐题点评（含一句音色播报）→ 总结报告；
7. **陪练与错题**：答 1 题（故意答差）→ 自动入错题本 → AI 抽问；
8. **兜底演示（加分项）**：展示一次断网/错 Key 下的错误提示与重试——体现工程健壮性；
9. **收尾**（30s）：技术亮点一句话——手写 Agent、SSE 全链路、**多账号数据隔离**、多供应商+模型级可切换、LLM 全 mock 测试、文档体系完整。

**数据准备**：验收演示前在演示环境预置**演示账号**（含已配置的 AI 供应商 Key）与一套数据（投递 10+ 条覆盖各状态、面经 3 篇、错题 5 条、模拟面试 2 场），确保登录后每个区块打开即有内容。

**应急预案**：外网故障 → 热点；LLM 限流 → 顺势演示"兜底提示+重试"环节；数据库损坏 → 备份文件恢复（演示前复制 app.db）。
