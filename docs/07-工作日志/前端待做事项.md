## 维护约定

1. **后端侧登记**：后端工作中产生、需要前端 / 测试侧配合的事项（改前端代码、补测试用例、动对方维护的文档章节等），**一律追加到本表表尾**；事项若涉及后端先行改动，已在[后端工作日志](后端工作日志.md) 对应节记录。
2. **前端侧回标**：事项完成后，由前端 / 测试侧把「状态」列改为 **`已完成（日期，执行人：卢世君）`**，并写明依据（文件 / 版本号 / 命令结果），同时更新上方「当前待处理」行，**不删行**。
3. **后端侧定期核对**：后端侧定期 `git fetch origin` 后对照 `origin/frontend` 的代码与文档，核对事项实际落地情况并回标，**不等对方通知、不等提醒**；两种回标方式并存，以最新一次为准。
4. 本表**只增不删**：完成的条目保留在表内作为协作记录。
5. 本文件位于 `docs/07-工作日志/`，属**公共文件**，改后需与 `frontend` 分支互相拉取同步（冲突以后端最新版为准）；**问题记录、测试计划的维护归属不变**（见[项目结构](../02-设计文档/项目结构.md) 第 1 节「跨职责文件区」）。
6. **与问题记录的分工（2026-09-26 起）**：问题记录中的条目按「**谁处理谁标注**」由处理方自行结案（见[问题记录](问题记录.md) 维护约定 8），**不登记为本表事项**；本表只登记需要前端 / 测试侧**实际动手**的事项。
