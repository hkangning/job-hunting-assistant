- `main.js` 挂载顺序：Pinia → Router → Element Plus（全量引入 + `zh-cn` locale）。

### 工作内容

**一、依赖引入（含一处实测排雷）**

新增 `vuedraggable` 与 `echarts` 两项依赖。两个坑：

- **装 vuedraggable 必须带 `@next`**：npm 的 `latest` 标签指向 2.24.3（Vue 2 版），直接 `npm i vuedraggable` 在本工程里装了个用不了的包；
- **vuedraggable 4.1.0 的入口是 UMD**：查证到其 `main` 与 `module` 字段**都**指向 `dist/vuedraggable.umd.js`，无 ESM 产物，社区有在 Vite 下报 `does not provide an export named 'default'` 的先例。**设计阶段做了三项实测排雷**（安装 → `npm run build` → Edge 无头渲染），确认本工程（Vite 8 + Vue 3.5.43）可用，故按用户选型继续。用法上必须写 `item-key` 与 `#item` 具名插槽。

**二、状态常量收敛为单一出处**

新增 `src/constants/application.js`：5 个状态的中文名、色值、合法流转表（含 `canTransit`）。同一份状态数据在看板列头与拖拽校验、表单状态展示、卡片状态点三处要用，散着写必然漂移。合法流转表与后端 `application_service.LEGAL_TRANSITIONS` 逐条对齐（SRS FR-004）。

**三、请求层补一处必要透传**

`request.js` 错误分支原先只透传 `code` / `httpStatus`，而导入「全行非法」时后端返回 **HTTP 400 + code=20002 + `data.errors` 行级清单**，前端拿不到清单就无法展示「哪一行错、为什么错」——而错误行展示正是本步的交付内容。补 `bizError.data = error.response.data.data` 一行。

**四、四个组件 + 页面容器**

页面 [Applications.vue](../../frontend/src/views/Applications.vue) 是唯一的数据持有者，四个子组件都是受控展示层（不直接调接口）：

| 组件 | 职责 | 关键设计 |
|---|---|---|
| `StatusKanban.vue` | 5 列看板 + 列间拖拽 | 见下方拖拽设计 |
| `ApplicationFormDialog.vue` | 新增/编辑表单 | 编辑时**状态只读**——接口文档 §3.3 明确 PUT 不改 status，放开会诱导用户改了不生效 |
| `ApplicationImportDialog.vue` | 模板下载/上传/结果展示 | 前端预校验（扩展名/≤2MB/非空）与后端限制一致，不合格不发请求 |
| `TrendChart.vue` | ECharts 折线趋势图 | 受控组件，数据由页面请求后传入；展开时才加载（懒加载） |

**五、拖拽合法性做双层校验**

- **前端预判**：`group.put` 读目标列与拖拽卡片各自的 `data-status` 查 `canTransit`，**非法落点直接拖不动**（sortablejs 拒绝），而不是拖过去再弹回——后者有视觉跳跃且说不清原因；
- **后端兜底**：被接受的拖拽走 `PATCH /applications/{id}/status`，失败则重新拉取列表以服务端数据为准；
- **终态保护**：`OFFER` / `CLOSED` 两列 `pull: false`，卡片出不去；`sort: false` 禁止列内排序（列内顺序由接口的 `applied_at DESC` 决定，允许拖动会导致刷新后顺序跳回）。

**六、顶栏与页面双向连通**

- **页面 → 顶栏**：`AppHeader` 的 actions 区加 Teleport 目标容器，投递页用 `<Teleport>` 注入「批量导入」按钮（设计文档 §4.4「页面级操作走 AppHeader 插槽」的落地方式，不引入状态库）；
- **顶栏 → 页面**：「＋ 新增投递」改为跳 `/applications?action=new`，页面 `watch` 该 query 打开表单后**立即 `router.replace` 清掉 query**——不清的话再次点击因导航目标相同而不触发，这是 query 方案的必要收尾。

### 决策与遗留

- **一处文档口径偏差（待步骤 21 终检）**：SRS FR-003 写批量导入为「解析后**预览 → 确认导入**」，但接口文档 §3.3 的 `POST /applications/import` 是**直接入库**、无预览端点。本次按接口文档执行（后端是唯一契约），前端以「选择文件 + 显式点『开始导入』」作为确认动作。两者口径不一致，终检时需统一（改 SRS 或增接口）；
